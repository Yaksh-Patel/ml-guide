Linear & Logistic Regression
The baseline you have to beat before you are allowed to ship anything else. Both models fit the same weighted sum of the features; one reads that sum as a quantity, the other as log-odds. Skip the step and you never find out whether the gradient-boosted ensemble bought you three points of AUC or three months of maintenance.
Linear regression is a projection
Every prediction the model can possibly make is a weighted sum of the feature columns — so the set of reachable predictions is the plane those columns span. Least squares picks the point on that plane closest to y. That is all fitting is: dropping a perpendicular from your target onto the space your features can reach.
$$\hat{y} = X\boldsymbol{\beta}, \qquad \hat{\boldsymbol{\beta}} = \arg\min_{\boldsymbol\beta}\ \underbrace{\|y - X\boldsymbol\beta\|^2}_{\text{squared length of the residual}}$$
Setting the gradient to zero gives the normal equations — "normal" as in perpendicular, because the residual must be orthogonal to every feature column, or you could still move closer.
$$X^{T}\underbrace{(y - X\boldsymbol\beta)}_{\text{residual}} = 0 \;\Longrightarrow\; \hat{\boldsymbol\beta} = (X^{T}X)^{-1}X^{T}y$$
Here X is n×p (rows are observations, columns are features), y is the n-vector of targets, and β is the p-vector of coefficients. The closed form is why linear regression is the one model that needs no optimiser.
Logistic regression is linear — just not in probability
The name confuses people because the output curve is obviously not a line. The resolution: the model is linear in the log-odds, and the sigmoid is only the change of units that brings log-odds back to a probability.
$$\underbrace{\log\frac{p}{1-p}}_{\text{log-odds (logit)}} = w^{T}x + b \qquad\Longleftrightarrow\qquad p = \sigma(z) = \frac{1}{1+e^{-z}}$$
Read left to right and it is a linear model. Read right to left and it is an S-curve. Same object. The logit is the natural scale for a probability because it stretches (0,1) onto the whole real line, so a linear function can no longer predict a probability of 1.4.
$$\mathcal{L} = -\frac{1}{n}\sum_i \Big[y_i \log \hat p_i + (1-y_i)\log(1-\hat p_i)\Big]$$
That loss is cross-entropy, and it is the maximum-likelihood objective for a Bernoulli outcome — not an arbitrary choice. It is also why logistic regression comes out roughly calibrated for free: log loss is a proper scoring rule, minimised only by the true probability.
The same linear core, one squashing function apart
What a logistic coefficient actually means
A linear coefficient is easy: β₁ = 2.5 means one more unit of x₁ adds 2.5 to the prediction, everywhere. A logistic coefficient is constant on the log-odds scale and therefore not constant on the probability scale, which is where nearly every misquote comes from.
Take β = 1.2. Exponentiate to get the odds ratio: e1.2 = 3.32. One extra unit of that feature multiplies the odds by 3.32 — and multiplying odds does very different things depending on where you start:

One coefficient, three different answers to "how much does the probability move". The effect peaks at p = 0.5 and dies at both extremes, because the slope of the sigmoid is p(1−p) — maximal at 0.5, near zero at the ends. Hence the useful shortcut: β/4 bounds the largest change in probability per unit (1.2/4 = 0.30, matching the middle row).
the sentence to say, and the one to avoid

Say: "a one-unit increase multiplies the odds of default by 3.3." Never say: "it raises the probability of default by 3.3×" or "by 1.2." The first is wrong about the quantity, the second quotes a log-odds as if it were a probability. If someone needs a probability answer, give the marginal effect at a stated operating point.

Why one has a closed form and the other does not
Both losses are convex, so both have a single global optimum with no local minima to get stuck in. The difference is whether you can solve for it algebraically.
$$\nabla_w \mathcal{L} = X^{T}\big(\underbrace{\sigma(Xw) - y}_{\text{prediction error}}\big)$$
The gradient has exactly the same shape as the linear case — features times error — but w is now trapped inside a sigmoid. Setting this to zero is a transcendental equation with no algebraic solution, so you iterate: lbfgs or Newton/IRLS, which converge in tens of iterations precisely because the problem is convex. "No closed form" is not the same as "hard to fit."
do not implement the normal equations

Forming XᵀX squares the condition number: κ(XᵀX) = κ(X)². With mildly collinear features at κ(X) ≈ 10⁴ you get κ(XᵀX) ≈ 10⁸, and double precision carries about 16 digits — so you have thrown away half your significant figures before the solve begins. sklearn uses an SVD-based least-squares routine on X directly and never forms XᵀX. Same reason PCA is computed by SVD rather than by eigendecomposing the covariance matrix.

The assumptions, and the symptom of each
Violating an assumption does not throw an exception. The model fits, prints coefficients, and quietly stops meaning what you think it means. What matters is knowing what you would observe.

Multicollinearity deserves a number. VIFj = 1/(1 − R²j), where R²j is from regressing feature j on all the others. At R² = 0.90 the VIF is 10 and the coefficient's standard error is inflated by √10 ≈ 3.2×. At R² = 0.99, VIF = 100 and the inflation is 10×. That is the mechanism behind "the sign flipped when I added a feature" — the interval was always wide enough to straddle zero, and you were reading noise.
Regularisation, and why L1 zeroes things
Add a penalty on coefficient size and you trade a little bias for a large drop in variance. The shape of the penalty decides what kind of solution you get.
  • Ridge (L2), λΣwᵢ²: shrinks every coefficient toward zero, reaching it only in the limit. The constraint region is a sphere — smooth everywhere, so the optimum lands off-axis with all features retained but tamed. This is the right default when features are correlated: ridge splits credit between them instead of picking one arbitrarily
  • Lasso (L1), λΣ|wᵢ|: produces exact zeros — genuine feature selection. The reason is geometric: the L1 ball is a diamond with corners sitting on the axes, and a corner is where a coordinate equals zero. Loss contours expanding outward touch a pointy vertex long before they touch a flat face, so the solution is sparse by construction, not by thresholding
  • Elastic Net, λ₁Σ|wᵢ| + λ₂Σwᵢ²: corners for sparsity, curvature for stability. The standard fix when you have groups of correlated features and pure lasso keeps picking a different member of the group on every bootstrap
Standardise before you regularise. The penalty charges per unit of coefficient, and a coefficient's size depends on its feature's units — so an unscaled model penalises a feature measured in dollars far less than the same feature measured in thousands of dollars. Regularising unscaled features means the units chose your model.
sklearn details that cause real bugs
  • C is the inverse penalty: C = 1/λ. Smaller C means more regularisation. C = 0.01 is heavy shrinkage, C = 100 is essentially none. The direction is backwards from every textbook and it is the single most common logistic-regression bug
  • LogisticRegression is regularised by default — L2 with C = 1.0. If you wanted plain maximum likelihood, or you are comparing against statsmodels output, you must ask for it explicitly. Silent shrinkage on an unscaled design matrix has ruined many coefficient tables
  • LinearRegression has no penalty and will happily hand back enormous coefficients on collinear data. Use Ridge the moment features are correlated
  • penalty='l1' needs a solver that supports it — liblinear or saga. The default lbfgs does not, and the error message is not obvious
  • class_weight='balanced' deliberately changes the base rate the model believes in. Useful for ranking, and it destroys calibration — recalibrate afterwards if the probability is going to be multiplied by money
Mistakes that survive code review
  • Ranking features by raw coefficient magnitude. Coefficients carry units. A β of 0.0001 on annual income in dollars is a bigger effect than a β of 2.0 on a 0/1 flag. Standardise first, or use permutation importance — and even standardised coefficients are unreliable under collinearity, because the split between two correlated features is arbitrary
  • Quoting a logistic coefficient as a probability change. It is a log-odds. Exponentiate it for an odds ratio, or state a marginal effect at a specific operating point. See the table above for why one number cannot answer the question
  • Getting C backwards. Grid-searching C over [1, 10, 100] and concluding "regularisation does not help" means you only ever tried almost none of it. Search log-spaced over both sides of 1
  • Regularising unscaled features. The penalty becomes a function of your units. Always put the scaler and the model in one Pipeline, so the scaler is refit inside every CV fold rather than on the full dataset
  • Assuming linear regression is unbiased about the mean when the target is skewed. Squared loss fits the conditional mean, which a long right tail drags upward. For revenue or claim sizes, model log(y) or use a Gamma/Tweedie GLM — and remember that exponentiating a prediction of log(y) gives back the median, not the mean
  • Reading p-values off a model fitted to engineered, selected features. Every threshold you tried and every feature you dropped after peeking is a hypothesis test you are not reporting. The intervals are narrower than reality by an unknown amount
  • Using linear regression on a bounded or count target. Predicting a probability with OLS gives you values below 0 and above 1, and there is no principled way to clip them. That is the problem logistic regression exists to solve
Why this is still everywhere
  • Credit scorecards are logistic regression by regulation, not by nostalgia. Weight-of-Evidence binning plus logistic regression gives a model where every point of the score traces to a stated reason, monotonic constraints can be enforced and proven, and a validation team can reproduce the whole thing in a spreadsheet. Explainability is a hard requirement under ECOA/Reg B, and this is the model that satisfies it without an approximation layer
  • It is the calibration layer on top of complex models. Google's ads stack ran logistic regression over billions of sparse features for years, and the pattern survived the move to deep learning: let the big model produce a score, then fit a one-dimensional logistic on held-out data to turn it into an honest probability. Platt scaling is logistic regression
  • Experiment analysis runs on linear models. A/B test lift, CUPED variance reduction, and difference-in-differences are all regressions. At experiment scale the CLT does the heavy lifting, and the interpretability of a coefficient is the entire point — you need to report an effect size with an interval, not a prediction
  • It is the baseline that decides whether the project is hard. Logistic regression on sensibly engineered features tells you the floor. If XGBoost beats it by 0.5% AUC, your problem is mostly linear and you should ship the simple model. If it beats it by 15%, there are real interactions worth chasing. Without the baseline you cannot tell those two worlds apart
  • The failure mode is the giveaway. When a linear model matches a boosted ensemble to three decimal places, check for leakage before celebrating: a single feature that encodes the future will let any model, including this one, look brilliant
🎯 In an interview

Lead with the log-odds framing. "Logistic regression is a linear model — linear in the log-odds. The sigmoid is just the inverse link that maps that back to a probability, and cross-entropy is the maximum-likelihood loss for a Bernoulli outcome." That single answer covers "why is it called regression", "why the sigmoid", and "why that loss" before they are asked separately.

Expect: "Interpret a coefficient of 1.2." — Exponentiate: the odds multiply by 3.3. Then volunteer the subtlety, because it is what separates candidates: the change in probability depends on where you start — about +0.27 near p = 0.5, only +0.07 near p = 0.9 — since the sigmoid's slope is p(1−p). Mentioning the β/4 rule shows you have used this rather than read it.

Expect: "Why does lasso select features and ridge not?" — Answer with the geometry, not the formula: the L1 constraint region has corners on the axes and an expanding loss contour hits a corner first, so a coordinate goes exactly to zero. The L2 region is a smooth sphere with no corners, so coefficients shrink but never vanish.

Do not say "the feature with the largest coefficient is the most important" (units), "logistic regression can't handle non-linearity" (it handles anything you put in the design matrix — splines, interactions, WoE bins), or "it's outdated" in a room that ships scorecards. Do say that you check VIF, standardise inside a pipeline, and remember that sklearn's C is 1/λ.

In code
The two workhorses side by side. The key line is the last one: logistic regression coefficients are log-odds, and exponentiating them is the only way to state them honestly.
import numpy as np
from sklearn.linear_model import LinearRegression, LogisticRegression
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
X = rng.normal(size=(1000, 3))
scaler = StandardScaler().fit(X)            # scaling matters once you regularise
Xs = scaler.transform(X)

# Linear: closed form exists, and sklearn uses it
y = 2*X[:,0] - 1.5*X[:,1] + rng.normal(0, .5, 1000)
lin = LinearRegression().fit(Xs, y)
print("linear coefs ", lin.coef_.round(3))

# Logistic: no closed form; it is convex, so IRLS/lbfgs converges reliably
z = 1.2*X[:,0] - 0.8*X[:,2]
yb = (rng.random(1000) < 1/(1+np.exp(-z))).astype(int)
log = LogisticRegression(C=1.0, max_iter=1000).fit(Xs, yb)

print("log-odds     ", log.coef_[0].round(3))
print("odds ratios  ", np.exp(log.coef_[0]).round(3))
# "a 1-sd increase in feature 0 multiplies the odds by ~3.3" -- the only
# statement about a logistic coefficient that is actually true
