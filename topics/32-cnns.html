Convolutional Neural Networks (CNNs)
A convolution is a fully-connected layer with two constraints imposed on it: each output may only look at a small neighbourhood, and every output must use the same weights. Both constraints are assumptions about images — that nearby pixels are related, and that a feature means the same thing wherever it appears. They cost you generality and buy a factor of a hundred million in parameters, which is the whole trade.
What weight sharing is worth
Take a 224 × 224 RGB image and produce 64 feature maps at the same resolution. Do it with a dense layer and then with a 3 × 3 convolution:
Weights
Fully connected — 150,528 inputs → 3,211,264 outputs483,000,000,000
3 × 3 convolution, 3 → 64 channels1,792 (1,728 weights + 64 biases)
Ratio: about 270,000,000 ×
Both layers map the same input shape to the same output shape. The dense version is not merely expensive, it is unlearnable — 4.8 × 10¹¹ parameters on any realistic dataset would fit noise perfectly and generalise not at all. The convolution's 1,792 numbers work because the constraints are true: an edge detector is useful at the top-left and equally useful at the bottom-right, so learning it once and reusing it everywhere is not a compromise, it is the correct model.
$$\text{out}_{i,j} = \sum_{m}\sum_{n} \text{in}_{i+m,\,j+n}\cdot K_{m,n} + b \qquad\qquad \text{out size} = \left\lfloor\frac{W - K + 2P}{S}\right\rfloor + 1$$

Receptive field: why 3 × 3 everywhere, and why you must downsample
A unit's receptive field is the region of the input that can influence it. Stacking small kernels grows it, and stacking is strictly better than using one big kernel:
ConfigurationReceptive fieldParams per channel pairNon-linearities
one 5 × 55 × 5251
two 3 × 35 × 518 — 28% fewer2
one 7 × 77 × 7491
three 3 × 37 × 727 — 45% fewer3
Same view of the input, fewer parameters, and more non-linearity — a strict win on all three counts. That is VGG's contribution and it is why essentially every modern architecture is built from 3 × 3 convolutions.
the arithmetic that forces pooling to exist

With stride-1 3 × 3 convolutions, the receptive field grows by exactly 2 per layer: after L layers it is 2L + 1. To let a unit see all 224 pixels of an image you would need 112 layers — and every one of them computing at full 224 × 224 resolution.

Downsampling changes the growth from additive to multiplicative: each stride-2 step doubles the receptive field measured in input pixels, so full coverage arrives in around fifteen layers instead of a hundred, and every layer after the first downsample costs a quarter as much compute. Pooling and strided convolution are not primarily about invariance — they are what makes the receptive field reachable at all.

1 × 1 convolutions, and the bottleneck they enable
A 1 × 1 convolution looks pointless — it sees one pixel. But it spans all the channels at that pixel, so it is a learned linear recombination of feature maps with no spatial component. That makes it the cheapest possible way to change channel depth, and it is what makes deep ResNets affordable.
Compare a plain 3 × 3 on 256 channels against the bottleneck design that replaces it:
DesignLayersWeights
Plain3 × 3, 256 → 256589,824
Bottleneck1 × 1, 256 → 64 (squeeze)16,384
3 × 3, 64 → 64 (the actual spatial work)36,864
1 × 1, 64 → 256 (expand)16,384
total69,632 — 8.5× fewer
The expensive 3 × 3 now operates on 64 channels instead of 256, and the two 1 × 1 layers cost almost nothing because they have no spatial extent. Spend your parameters on spatial mixing at low channel depth, and on channel mixing at zero spatial extent — that factorisation is why ResNet-50 has fewer parameters than VGG-16 while being twice as deep.
Depthwise separable convolution takes the same idea further, splitting a convolution into per-channel spatial filtering followed by a 1 × 1 channel mix. That is the core of MobileNet and EfficientNet, and it is why on-device vision models are as small as they are.
Residual connections, and the term that matters
Before ResNet, adding layers past a certain depth made networks worse on training data — not an overfitting problem but an optimisation one. The fix is one addition:
$$y = F(x) + x \qquad\Longrightarrow\qquad \frac{\partial L}{\partial x} = \frac{\partial L}{\partial y}\left(1 + \frac{\partial F}{\partial x}\right)$$
The whole contribution is that "1". Recall that the gradient reaching an early layer is a product of one factor per layer, so a typical factor even slightly below 1 vanishes exponentially in depth. A residual block's factor is (1 + something) rather than something — there is a path through the network that multiplies by exactly 1, so the product cannot decay to nothing no matter how deep the stack. That is why 100-layer networks became trainable, and it is why every transformer block is also a residual block.
The complementary framing is about what is easy to learn: if the best thing a block can do is nothing, F only has to learn to output zero, which is far easier than learning to reproduce the identity through a stack of weights and non-linearities. The default behaviour becomes "pass through unchanged", and extra depth stops being able to hurt.
Equivariance, invariance, and where the parameters go
These two words get used interchangeably and they are different properties, only one of which convolution actually has.
  • Convolution is translation equivariant — shift the input and the feature map shifts by the same amount. The representation moves with the object; it does not ignore position
  • Pooling adds approximate invariance — small shifts within a pooling window produce the same output, so the response stops depending on exact position
  • Global average pooling gives full invariance — collapsing each feature map to its mean discards position entirely, leaving only "how much of this feature is present"
  • Neither gives rotation or scale invariance. A CNN does not recognise an upside-down cat unless it saw upside-down cats, which is precisely why rotation and scale augmentation matter so much
where VGG's parameters actually went

VGG16 holds roughly 138M parameters, and its first fully-connected layer — 7 × 7 × 512 flattened to 4,096 — accounts for 102,760,448 of them. That is 74% of the entire network in a single layer, sitting after all the convolutional work is done.

Global average pooling replaces that layer with 512 → 1,000 = 512,000 parameters, a 200× reduction, and typically improves generalisation because it removes the location sensitivity a flatten introduces. It is why modern architectures end in GAP rather than flatten, and it is the clearest example of an architectural change that saves parameters and accuracy simultaneously.

Max versus average pooling: max asks "is this feature present anywhere in the window", which suits detecting a thing; average asks "how strong is it on average", which suits summarising. Max in intermediate layers, global average before the classifier is the standard combination.

Mistakes that survive code review
  • Training from scratch when pretrained weights exist. ImageNet features transfer remarkably well even to X-rays and satellite imagery, because the early layers learn edges and textures that are genuinely universal. Fine-tuning is far cheaper and usually more accurate. On 10,000 images, from-scratch training is almost never right
  • Large kernels instead of stacked 3 × 3. Two 3 × 3 beat one 5 × 5 on parameters, non-linearity and receptive field simultaneously
  • Flatten instead of global average pooling. The 74%-of-VGG number is the argument. GAP is fewer parameters, position-invariant, and a regulariser
  • BatchNorm at small batch size. Statistics from four samples are noise. Detection and segmentation at high resolution often force small batches — use GroupNorm there
  • Forgetting model.eval(). BatchNorm then uses batch statistics at inference, so predictions depend on what else is in the request. A genuinely nasty production bug
  • Normalising with the wrong statistics. A pretrained backbone expects the mean and standard deviation its weights were trained with. Using your own dataset's statistics with ImageNet weights quietly degrades everything
  • Augmenting in ways that destroy the label. Horizontal flips are free on natural images and wrong for text or for medical scans where laterality is diagnostic. The augmentation set encodes what you claim is invariant — get it wrong and you are training the model to ignore signal
  • Assuming the model is scale or rotation invariant. It is not, unless you augmented for it
  • Not checking the receptive field covers the object. If your target spans 200 pixels and the architecture's receptive field is 60, no amount of training fixes it. It is arithmetic you can do before training
Where CNNs stand now
  • They did not lose — the story is data-dependent. Vision transformers have no locality or translation bias, so they must learn spatial structure from data. Above roughly 100M images that freedom wins; below it the CNN's built-in assumptions are worth more than the flexibility. Most teams are in the second regime, which is why convnets remain the pragmatic default
  • The architectures converged. Modern convnets adopted transformer-era ingredients — larger kernels, LayerNorm, GELU, inverted bottlenecks — and closed much of the gap, which suggests a good deal of ViT's advantage was training recipe rather than attention itself
  • Transfer learning is the actual production workflow. A pretrained backbone plus a task head, fine-tuned. The interesting engineering is in data, augmentation and evaluation, not in architecture — and this is why FDA-cleared medical imaging models are usually a standard backbone rather than something bespoke
  • Multi-task shared backbones at the edge. Automotive stacks run one backbone over camera input with several heads — detection, segmentation, depth — because the backbone is the expensive part and the features are shared. Latency and power budgets, not accuracy, drive those designs
  • Convolution's real legacy is the inductive-bias lesson. Weight sharing and locality turned an unlearnable 4.8 × 10¹¹-parameter problem into a 1,792-parameter one by encoding something true about the domain. That trade — constrain the model with a real assumption and buy back orders of magnitude of data efficiency — is the transferable idea, and it applies well beyond images
🎯 In an interview

Frame convolution as a constrained dense layer. "It is a fully-connected layer with locality and weight sharing imposed. On a 224 × 224 × 3 input to 64 feature maps, dense would need 4.8 × 10¹¹ weights and a 3 × 3 conv needs 1,792 — about 270 million times fewer. It works because the constraints are true of images." That answer explains both what a convolution is and why it exists.

Be able to compute output shapes live: ⌊(W − K + 2P)/S⌋ + 1, and know that P = (K−1)/2 gives "same" padding for odd K. Then the receptive-field point that most candidates miss: with stride-1 3 × 3 convs the field grows as 2L + 1, so covering 224 pixels would take 112 layers — downsampling exists to make the receptive field reachable, not mainly to provide invariance.

Expect: "Why did ResNet enable deeper networks?" — The gradient becomes ∂L/∂y · (1 + ∂F/∂x). Since the gradient reaching an early layer is a product of per-layer factors, that "+1" guarantees a path multiplying by exactly 1, so the product cannot vanish. Add the learning-side framing: if the best action is to do nothing, F only has to output zero, so extra depth cannot hurt.

Two things that read as real experience: that 74% of VGG16's parameters are in its first FC layer, which is why everything now ends in global average pooling; and that convolution is translation equivariant while pooling supplies approximate invariance — and neither gives you rotation or scale, so that has to come from augmentation.

In code
A convolution done by hand, then the output-size formula that every CNN interview asks for, then the same layer in PyTorch so the shapes line up.
import numpy as np

# 2D convolution from scratch — correlation, really; frameworks skip the flip
def conv2d(x, k, stride=1, pad=0):
    x = np.pad(x, pad)
    kh, kw = k.shape
    oh = (x.shape[0] - kh) // stride + 1
    ow = (x.shape[1] - kw) // stride + 1
    return np.array([[np.sum(x[i*stride:i*stride+kh, j*stride:j*stride+kw] * k)
                      for j in range(ow)] for i in range(oh)])

img = np.arange(36, dtype=float).reshape(6, 6)
sobel_x = np.array([[-1, 0, 1], [-2, 0, 2], [-1, 0, 1]], dtype=float)
print("out shape", conv2d(img, sobel_x, stride=1, pad=1).shape)   # 6x6, 'same'

# The formula: floor((W - K + 2P) / S) + 1.  Memorise this one.
size = lambda W, K, P, S: (W - K + 2*P) // S + 1
print("224 -> ", size(224, 7, 3, 2), "-> ", size(size(224,7,3,2), 3, 1, 2))  # ResNet stem

# Parameter count is independent of input size — the whole point of weight sharing
Cin, Cout, K = 64, 128, 3
print("conv params", Cin*Cout*K*K + Cout, "vs dense on 56x56:", 56*56*Cin*Cout)

import torch, torch.nn as nn
block = nn.Sequential(nn.Conv2d(3, 64, 7, stride=2, padding=3, bias=False),
                      nn.BatchNorm2d(64), nn.ReLU(inplace=True),
                      nn.MaxPool2d(3, stride=2, padding=1))
print("torch out", block(torch.randn(1, 3, 224, 224)).shape)   # [1, 64, 56, 56]
