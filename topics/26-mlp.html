Perceptron & Multi-Layer Perceptron
A neural network is a stack of linear maps with a non-linearity wedged between each pair. Take the non-linearities out and the whole tower algebraically collapses into a single matrix — no matter how many layers you built. That collapse is the cleanest way to see what the activation function is for, and what depth actually buys you.
The perceptron, and the wall it hit
A perceptron is a weighted sum passed through a threshold. Geometrically it draws one hyperplane and reports which side you are on — so it can learn any pattern that a single straight cut separates, and nothing else.
$$z = w^{T}x + b, \qquad \text{output} = \text{activation}(z)$$
AND and OR are one cut each, so a perceptron handles both. XOR is not, and that is not a limitation of the training rule — no single straight line separates {(0,1), (1,0)} from {(0,0), (1,1)}, so no perceptron exists that computes it. Minsky and Papert made this precise in 1969 and the field's enthusiasm collapsed for a decade.
The fix is one hidden layer, and it is small enough to write out completely. Two ReLU units:
$$h_1 = \text{ReLU}(x_1 + x_2 - 0.5), \qquad h_2 = \text{ReLU}(x_1 + x_2 - 1.5), \qquad y = 2h_1 - 6h_2$$
x₁, x₂h₁ = ReLU(x₁+x₂−0.5)h₂ = ReLU(x₁+x₂−1.5)y = 2h₁ − 6h₂XOR

Read what the hidden units learned to be: h₁ fires when at least one input is on, h₂ fires only when both are on. That is OR and AND — two linear separations — and XOR is then their difference. The hidden layer did not find a cleverer straight line; it built new features, and in that new space the problem became linearly separable. That is what every hidden layer does, and everything below is that idea repeated.
Multi-Layer Perceptron — forward pass signal flow
Without the non-linearity, depth is an expensive illusion
Stack two linear layers and the composition is still linear — the product of two matrices is a matrix:
$$W_3\big(W_2(W_1x)\big) = \underbrace{(W_3W_2W_1)}_{\text{a single matrix}}x$$
Put numbers on the waste. A 784 → 256 → 256 → 10 network — the standard MNIST shape — holds 269,322 parameters including biases. Strip the activations and every one of those collapses into an equivalent 784 × 10 map: 7,840 effective degrees of freedom. You would be storing and training 269,322 numbers to express something a 34× smaller model expresses exactly.
So the activation is not a detail applied to a layer's output — it is the thing that makes the layer a layer. This is also the fastest way to diagnose a network that will not learn past linear-model performance: check that a non-linearity is actually present between every pair of weight matrices, because a missing one is silent.
Parameter counting is worth being fluent in, since it comes up constantly. A layer mapping m inputs to n outputs holds m·n weights plus n biases:

Note where the parameters live: the first layer holds 75% of them, because 784 inputs is wide. That is why the input representation dominates the memory budget of small MLPs, and why convolutions — which share weights across positions — were such a large win on images.
Why depth beats width
The universal approximation theorem says a single hidden layer can approximate any continuous function to arbitrary accuracy. It is often quoted as though it settles the architecture question. It does not, because it says nothing about how wide that layer has to be — and the answer can be exponential.
The clean example is a sawtooth. Each ReLU layer can fold the input space back on itself, and folding composes: L layers of a couple of units each produce roughly 2L linear segments. A single hidden layer has no folding to compose, so it needs one unit per segment.
Function with 2¹⁰ = 1,024 teethUnits needed
Deep — 10 layers, folding at each~20
Shallow — one hidden layer~1,024
Depth is exponentially more parameter-efficient than width for compositional functions — and the functions we care about are compositional: pixels form edges, edges form textures, textures form parts, parts form objects. Each layer reuses what the layer below built, which is why the same total parameter count buys far more when arranged deep than wide.
The catch is that depth is a representational win and an optimisation cost. A deep network can express the function; getting gradient descent to find it is a separate problem, and the reason very deep networks were untrainable until residual connections, normalisation layers and better initialisation arrived. Expressiveness was never the bottleneck.
The forward pass, and reading the loss curve
$$h^{(1)} = \phi\big(W^{(1)}x + b^{(1)}\big), \qquad h^{(2)} = \phi\big(W^{(2)}h^{(1)} + b^{(2)}\big), \qquad \hat y = g\big(W^{(3)}h^{(2)} + b^{(3)}\big)$$
φ is the hidden activation — ReLU or GELU. g is chosen by the task, not by preference: identity for regression, sigmoid for binary, softmax for single-label multi-class, independent sigmoids for multi-label. Never ReLU, which would clip half the output range.
Normalise the inputs. Beyond the conditioning argument that applies to any gradient method, there is a reason specific to the first layer: its weight gradient is proportional to the input value, so a feature measured in tens of thousands produces gradients four orders of magnitude larger than a feature in [0,1]. One learning rate cannot serve both, and the large-scale feature effectively sets the step size for the whole layer.
The validation loss curve is the primary instrument, and its shapes are diagnostic:

That last row deserves emphasis: before any real training run, take ten examples and confirm the network can drive its loss to near zero on them. If it cannot memorise ten rows, the problem is wiring — a detached gradient, a label misalignment, a frozen layer — and no amount of tuning will fix it.
Mistakes that survive code review
  • Reaching for an MLP on small tabular data. Below roughly 100k rows, gradient-boosted trees almost always win, and the reason is structural rather than about tuning effort — see the next card. Benchmark against a tree model first; it takes minutes and it sets the bar
  • Forgetting to normalise inputs. Silent, and it makes one feature set the effective learning rate for the entire first layer
  • Sigmoid or tanh in hidden layers. Both saturate, so gradients die in depth. ReLU or GELU for hidden layers; sigmoid belongs at a binary output, and tanh belongs inside an LSTM cell where bounded state is the point
  • ReLU on the output layer. Clips every negative prediction to zero. Regression needs the whole real line, probabilities need sigmoid or softmax
  • Adding depth to fix underfitting when the loss is flat. A flat loss is usually a bug. Overfit ten samples first, then scale
  • Treating "universal approximator" as an argument for using one. It says a wide enough single layer can represent the function. It says nothing about whether you have the data to find it or the optimiser to reach it
  • Adding layers without normalisation or residuals. Past a handful of layers, plain stacks train badly. The machinery that makes depth trainable is not optional at depth
  • Skipping the seed and the loss curve. Neural network runs vary; without a fixed seed and a plotted curve you cannot tell a real improvement from a lucky initialisation
Where MLPs win, and where they honestly do not
  • They lose on tabular data for a structural reason. Repeated head-to-head studies find boosted trees ahead on typical tabular problems, and the explanation is about inductive bias, not tuning: tree ensembles are piecewise-constant and axis-aligned, which matches tabular targets that jump at thresholds and have irregular, non-smooth structure. An MLP imposes smoothness that the data does not have, and it has no native handling for mixed types or missing values. Knowing why is more useful than knowing the benchmark
  • They are the component, not the model. The MLP rarely appears alone in modern systems — it is the feed-forward block inside every transformer layer, the "deep" half of wide-and-deep recommenders, and the head on top of a pretrained encoder. Most of the MLPs running in production today are two-layer blocks inside something larger
  • They win where the input is already a learned representation. Once a CNN or a language model has produced an embedding, a small MLP on top is exactly the right tool: the hard representational work is done, and what remains is a smooth mapping to the output
  • They win in scientific ML at small data. Physics-informed networks fit an MLP to a differential equation's solution, using the equation itself as part of the loss. Unusual because it is a small-data regime where neural nets dominate — the network's smoothness is exactly the right prior when you are approximating a smooth physical field
  • The honest summary: reach for an MLP when the input is perceptual, sequential, or already embedded, and when you have enough data to pay for the flexibility. On a spreadsheet with 20,000 rows, use the trees
🎯 In an interview

Lead with the collapse. "Without activations, W₃W₂W₁x is a single matrix — a 784-256-256-10 net has 269,322 parameters expressing something a 784×10 map expresses exactly, so all the depth is wasted. The non-linearity is what makes a layer a layer." Concrete, and it proves you understand the mechanism rather than the slogan.

Expect: "Why does depth help more than width?" — Universal approximation guarantees one hidden layer suffices but says nothing about width, and the width required can be exponential. A sawtooth with 1,024 teeth needs about 20 units arranged deep and about 1,024 arranged flat, because layers compose — each folds what the one below produced. Then add the qualification that separates people: depth is a representational win and an optimisation cost, which is why residuals and normalisation had to be invented before deep networks were trainable.

Have XOR ready. A single perceptron is one hyperplane, so XOR is impossible — not hard, impossible. Two hidden ReLU units solve it because they learn OR and AND, and XOR is their difference. Being able to state the units' roles shows you understand hidden layers as feature construction rather than as extra capacity.

The practical answer they want to hear: "On tabular data I benchmark XGBoost first, because trees are axis-aligned and piecewise-constant and tabular targets usually are too." And volunteer the debugging habit: overfit ten samples before launching a real run — if the network cannot memorise ten rows, it is a wiring bug, not a hyperparameter.

In code
A two-layer network built with nothing but NumPy — forward pass, loss, manual backward pass, update. Every framework is this with more bookkeeping.
import numpy as np

rng = np.random.default_rng(0)
X = rng.normal(size=(500, 4))
y = (X[:, 0] * X[:, 1] > 0).astype(float)[:, None]   # XOR-ish: needs a hidden layer

# He initialisation for ReLU: variance 2/fan_in keeps activations alive
W1 = rng.normal(0, np.sqrt(2/4), (4, 16)); b1 = np.zeros(16)
W2 = rng.normal(0, np.sqrt(2/16), (16, 1)); b2 = np.zeros(1)
lr = 0.05

for epoch in range(2001):
    # forward
    z1 = X @ W1 + b1
    a1 = np.maximum(0, z1)                 # ReLU
    z2 = a1 @ W2 + b2
    p = 1 / (1 + np.exp(-z2))              # sigmoid
    loss = -np.mean(y*np.log(p+1e-9) + (1-y)*np.log(1-p+1e-9))

    # backward — dL/dz2 collapses to (p - y) for sigmoid + BCE, which is
    # the reason that pairing is the default
    dz2 = (p - y) / len(X)
    dW2, db2 = a1.T @ dz2, dz2.sum(0)
    da1 = dz2 @ W2.T
    dz1 = da1 * (z1 > 0)                   # ReLU derivative is a mask
    dW1, db1 = X.T @ dz1, dz1.sum(0)

    for p_, g in ((W1, dW1), (b1, db1), (W2, dW2), (b2, db2)):
        p_ -= lr * g

    if epoch % 500 == 0:
        print(f"epoch {epoch:4d}  loss {loss:.4f}  acc {((p>.5)==y).mean():.3f}")
