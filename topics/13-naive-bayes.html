Naive Bayes Classifier
A model that is demonstrably wrong about how the data was generated and reliably right about which class it belongs to. That gap is the whole lesson: an assumption can be false and still be worth making, if what it buys you is the ability to estimate anything at all from the data you actually have. Trains in one pass, predicts in microseconds, and remains the honest baseline for text when labels are scarce.
Where the assumption comes from — and what it buys
Start with Bayes' rule. You want the probability of a class given the observed features; what you can count from data is the reverse.
$$P(y \mid x_1,\ldots,x_d) = \frac{\overbrace{P(y)}^{\text{prior}}\ \overbrace{P(x_1,\ldots,x_d \mid y)}^{\text{likelihood}}}{\underbrace{P(x_1,\ldots,x_d)}_{\text{same for every class}}}$$
The denominator does not depend on y, so for picking the winning class you can drop it. The prior is a class frequency — trivial to count. Everything hard is in that likelihood term, and it is hard for a reason worth quantifying.
Suppose just 20 binary features. The full joint distribution P(x₁,…,x₂₀ | y) is a table with one entry per combination of feature values: 2²⁰ − 1 = 1,048,575 parameters, per class. On a typical text problem you have maybe 800 labelled documents. You cannot estimate a million parameters from 800 examples; most cells would be empty and the rest would be noise.
Assume the features are conditionally independent given the class, and the joint factors into a product of one-dimensional pieces:
$$P(x_1,\ldots,x_d \mid y) \approx \prod_{i=1}^{d} P(x_i \mid y) \qquad\Longrightarrow\qquad \hat y = \arg\max_y \Big[\log P(y) + \sum_{i=1}^{d}\log P(x_i \mid y)\Big]$$
the actual trade

That one assumption takes the model from 1,048,575 parameters you cannot estimate down to 20 you can — one per feature per class, each a simple count. The assumption is not there because anyone believes it. It is there because the alternative is not estimable. Naive Bayes is the clearest example in this atlas of a bias deliberately accepted to kill variance.

Why being wrong does not cost it the answer
Words in text are obviously not independent given the class — "space" and "shuttle" travel together, and the model counts each as fresh, unrelated evidence. So it double-counts, triple-counts, and its output probabilities are badly distorted. Classification does not need the probability to be right. It needs the argmax to be right.
Watch what the distortion actually does. Say the honest posterior for a document is P(spam | x) = 0.60, which is log-odds log(0.60/0.40) = +0.41. Now suppose three correlated spam words each contribute their evidence in full, when jointly they should have contributed once — adding roughly +2.8 of spurious log-odds:
log-oddsimplied P(spam)decision at 0.5
honest posterior+0.410.60spam
Naive Bayes, evidence triple-counted+3.210.96spam
The probability is off by 36 percentage points. The decision is identical. That is the mechanism in a sentence: the independence violation inflates the magnitude of the log-odds but rarely flips its sign, because the double-counted evidence pushes in the direction the evidence already pointed. Domingos & Pazzani (1997) formalised this — Naive Bayes is optimal for zero-one loss over a far wider range of conditions than it is for probability estimation.
The corollary is the one rule to remember: use the ranking, never quote the probability. Its scores pile up against 0 and 1 and are among the worst-calibrated of any common classifier. If you need a real probability out of it, fit Platt scaling on held-out data.
The independence assumption is false and it still works
Log space, and the number that forces it
Notice the argmax above sums logs rather than multiplying probabilities. That is not stylistic tidiness — the direct product does not survive contact with a real document.
Take a 200-word document where a typical word has P(wᵢ | y) ≈ 10⁻⁴. The likelihood is:
$$\prod_{i=1}^{200}10^{-4} = 10^{-800} \qquad\text{vs}\qquad \sum_{i=1}^{200}\log(10^{-4}) = 200 \times (-9.21) = -1842$$
A 64-bit float bottoms out near 10⁻³⁰⁸. So 10⁻⁸⁰⁰ is not a small number — it is stored as exactly 0.0. And it is 0.0 for every class, so the argmax has no information left to compare and returns whichever class happens to be first. The failure mode is a classifier that silently predicts one constant label and never raises an error. Meanwhile −1842 sits comfortably in range, and comparing −1842 against −1907 is a perfectly well-conditioned decision.
Every library does this internally — sklearn exposes feature_log_prob_, not feature_prob_. It matters when you implement it yourself, and it is the standard interview probe on this topic. If you need the posterior back on a 0–1 scale, use the log-sum-exp trick rather than exponentiating and normalising.
The zero-frequency problem: smoothing turns a veto into a penalty
A product has a fatal property — one zero factor zeroes the whole thing. If a word never appeared in class c during training, its estimate is 0/N = 0, so log 0 = −∞, and that single unseen word eliminates class c no matter what the other 199 words say. A word absent from your training sample gets to overrule all the evidence you do have.
Laplace (add-α) smoothing pretends you saw every vocabulary word α extra times. With a class holding 5,000 tokens over a 10,000-word vocabulary:
Word's count in class cUnsmoothed Plog PAdd-1 smoothed Plog P
0 (never seen)0 / 5,000 = 0−∞ — class eliminated1 / 15,000 = 6.7e-5−9.6 — a penalty

The denominator is 5,000 + α·V = 15,000, not 5,000 — the added pseudo-counts have to be accounted for or the probabilities no longer sum to one. Note what happens in the second row: smoothing also pulls observed estimates down toward uniform. That is the point. α is a regularisation strength, and it is the one hyperparameter here worth tuning: α = 1 is the safe default, α → 0 restores the veto, α large flattens everything toward the prior and the model stops discriminating.
Variants — pick by the shape of the feature
The independence assumption is fixed; the choice is which one-dimensional distribution you fit to each feature. Get this wrong and the model is misspecified in a way no amount of tuning recovers.

The most common misspecification is Gaussian NB on word counts. Counts are discrete, non-negative and mostly zero; a Gaussian fitted to them has a mean near zero, a huge variance, and puts mass on negative counts. It runs and returns a mediocre score, so nothing tells you the model was the wrong one.
What it actually costs to train
  • Training is one pass and a division. Count how often each feature co-occurs with each class, divide, take logs. There is no optimiser, no learning rate, no epochs — nothing to converge and nothing to diverge. O(n · d̄) where d̄ is the average number of non-zero features per row
  • Prediction is one dot product per class over the non-zero features of the query. Microseconds on CPU, no GPU, no batching. This is why it persists as a first-pass filter in front of expensive models
  • It is trivially incremental. partial_fit is exact rather than approximate — you are adding to counts. New labelled data updates the model without a retrain, which is unusual and genuinely useful for streaming
  • It works at small n better than almost anything else. Twenty parameters per class per feature can be estimated from hundreds of documents; that is the regime where it beats a fine-tuned transformer not on accuracy ceiling but on the accuracy you can actually reach with the labels you have
The flip side is a hard ceiling: the model cannot represent a feature interaction. "Free" and "money" together being more suspicious than the sum of each alone is exactly what independence forbids. Give it enough data and any interaction-capable model overtakes it — which is why the sensible framing is "the baseline you must beat", not "the model you ship".
Mistakes that survive code review
  • No smoothing. One unseen word sends a class to −∞ and the prediction is decided by vocabulary coverage rather than evidence. Setting alpha=0 to "avoid biasing the estimates" restores exactly this bug
  • Multiplying raw probabilities. Underflows to 0.0 for every class on any document of realistic length, and then predicts a constant label with no error raised. Sum logs
  • Quoting its probabilities. 0.98 from Naive Bayes does not mean 98%. The independence violation compounds the log-odds, so scores bunch at the extremes. Fine for ranking or thresholding; never multiply one by a dollar amount
  • Gaussian NB on bag-of-words. Wrong distribution for the data. Multinomial for counts and TF-IDF, Bernoulli for presence on short text
  • Forgetting the smoothed denominator. Adding α to the numerator without adding α·V to the denominator gives you something that is not a probability distribution. Easy to get wrong in a from-scratch implementation and it barely shows in the accuracy
  • Reading "naive" as "bad". It refers to the independence assumption about features, not the quality of the model. It is competitive on small-sample text and it is the standard comparator in the literature for a reason
  • Deduplicating features and expecting no change. Because each feature is counted as independent evidence, keeping two near-identical columns doubles their influence. Removing redundant features materially changes the output — unlike in a model that can share credit between correlated inputs
  • Using it on an imbalanced corpus without Complement NB. The majority class's counts swamp the estimates and the model collapses toward predicting it
Where it still earns its place
  • The cheap first stage in a cascade. Spam and abuse pipelines put a Naive Bayes filter in front of the expensive classifiers: it disposes of the obvious cases at microsecond cost and passes only the ambiguous ones downstream. The economics of the stack, not accuracy, is the argument
  • Real-time text tagging. Newsroom and market-data topic tagging at wire-service latency, where the budget is microseconds per document and no GPU is in the path. A 1–2% accuracy gap is a fair price for that
  • Low-label domains. Clinical note classification and ICD coding often have a few hundred labelled examples of a category. With that little data the variance of a high-capacity model dominates its lower bias, and Naive Bayes wins on the bias–variance trade rather than on sophistication
  • Streaming and drifting content. Exact incremental updates via partial_fit mean the model can absorb new labels continuously — valuable in adversarial settings where spammers change vocabulary faster than a retrain cycle
  • The baseline in every paper. Naive Bayes with bigrams remains the standard comparator for sentiment and topic classification. If a new architecture cannot clear it by a comfortable margin on your data, the result is about your data, not the architecture
🎯 In an interview

The question is always some form of "why does it work when the assumption is false". Answer with the argmax argument: "classification needs the right class to win, not the probabilities to be accurate. The independence violation inflates the magnitude of the log-odds because correlated evidence gets counted twice, but it rarely flips the sign — so the ranking survives and the calibration does not. It is a well-ordered, badly-calibrated model."

Then give the reason the assumption exists, which most candidates skip: the full joint over 20 binary features is 2²⁰ ≈ a million parameters per class, and independence reduces that to 20. It is a deliberate bias-for-variance trade, not laziness. This is the answer that sounds like someone who has thought about it.

Expect the two implementation probes. Smoothing: without it one unseen word zeroes an entire class, so add-α turns an infinite veto into a finite penalty — and remember α·V in the denominator. Log space: a 200-word document multiplies out to about 10⁻⁸⁰⁰, float64 stops at 10⁻³⁰⁸, so the naive product is 0.0 for every class and the classifier silently returns a constant.

Do not say "it's too simple to be useful" — it is the standard baseline and a live production filter. Do volunteer the ceiling: it cannot represent feature interactions, which is precisely why more data eventually favours a model that can.

In code
The "naive" assumption is wrong on essentially every real dataset, and the classifier still works. This shows why: the decision only needs the argmax to be right, not the probabilities.
import numpy as np
from sklearn.datasets import fetch_20newsgroups
from sklearn.feature_extraction.text import CountVectorizer
from sklearn.naive_bayes import MultinomialNB
from sklearn.pipeline import make_pipeline
from sklearn.metrics import accuracy_score

cats = ['sci.space', 'rec.autos']
tr = fetch_20newsgroups(subset='train', categories=cats, remove=('headers','quotes'))
te = fetch_20newsgroups(subset='test',  categories=cats, remove=('headers','quotes'))

# alpha is Laplace smoothing: without it one unseen word zeroes the whole product
model = make_pipeline(CountVectorizer(min_df=2), MultinomialNB(alpha=1.0)).fit(tr.data, tr.target)
print("accuracy", accuracy_score(te.target, model.predict(te.data)).round(4))

# Words are obviously not independent given the class ("space shuttle"),
# yet the argmax survives because errors in the product tend to cancel.
vec, nb = model.named_steps['countvectorizer'], model.named_steps['multinomialnb']
vocab = np.array(vec.get_feature_names_out())
llr = nb.feature_log_prob_[1] - nb.feature_log_prob_[0]
print("most sci.space :", vocab[llr.argsort()[-6:]][::-1])
print("most rec.autos :", vocab[llr.argsort()[:6]])
