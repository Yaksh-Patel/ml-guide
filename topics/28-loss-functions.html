Loss Functions
The loss is not a scoring rule bolted onto training — it is the only statement of what you want, and every gradient the model ever sees comes from it. Each loss also encodes a probability model whether you chose one or not: squared error assumes Gaussian noise, absolute error assumes Laplace, cross-entropy assumes Bernoulli. Picking a loss is picking that assumption, and the failures in this topic are almost all cases of the assumption not matching the data.
Every loss is a likelihood in disguise
Losses look arbitrary until you write down where they come from. Assume a noise distribution, take the negative log-likelihood of your data under it, and the standard losses fall out — which is why they have exactly the forms they do rather than any other reasonable-looking formula.

The third column is the practical payoff. Squared error fits the conditional mean, and a long right tail drags the mean upward — so a model trained with MSE on revenue or claim sizes systematically over-predicts the typical case. Absolute error fits the median, which is usually what "a typical value" means to whoever asked. This is a modelling decision disguised as a loss choice, and most people make it by accident.
It also explains why cross-entropy comes out roughly calibrated for free while squared error on class labels does not: cross-entropy is the maximum-likelihood objective for a probability, so it is a proper scoring rule — minimised only by the true probability, and therefore impossible to game by shifting scores around.
Regression losses, and what each does with an outlier
$$\text{MSE} = \frac{1}{n}\sum(y-\hat y)^2 \qquad \text{MAE} = \frac{1}{n}\sum|y-\hat y| \qquad \text{Huber}_\delta = \begin{cases}\tfrac{1}{2}e^2 & |e| \le \delta \\[2pt] \delta|e| - \tfrac{1}{2}\delta^2 & |e| > \delta\end{cases}$$
What separates them is the gradient, not the loss value — the gradient is what actually moves the weights. For squared error the gradient grows linearly with the error, so a single far-off point can dominate an entire batch:

One point at error 100 contributes as much gradient as a hundred points at error 1. If that point is a data-entry mistake, MSE will happily bend the whole model to accommodate it. MAE and Huber cap the per-example gradient at a constant, so no single row can hijack the update — that is the entire content of "robust to outliers".
Huber is the practical default when you are unsure: quadratic within δ, so it keeps MSE's smooth, well-behaved gradient near the optimum, and linear beyond δ, so it keeps MAE's robustness in the tails. δ is a real hyperparameter — it is the error magnitude at which you stop believing the point — and it must be set in the units of your target, so scale matters.
Quantile (pinball) loss deserves a mention because it does something the others cannot. Weighting under- and over-prediction asymmetrically makes the model fit a chosen quantile instead of a central value. Train at the 10th and 90th percentiles and you have a prediction interval rather than a point estimate — which is how demand and inventory forecasts get uncertainty bounds without a probabilistic model.
Why Average Cross-Entropy (ACE) Beats Classification Error and MSE
Consider two classifiers predicting political affiliation (Democrat / Republican / Other) — both get 2 out of 3 examples correct, so both have identical classification error = 1/3. But they are clearly not equally good:
Classifier A — barely correct
Computed | Target | Correct? 0.3 0.3 0.4 | 0 0 1 ✓ | yes (barely) 0.3 0.4 0.3 | 0 1 0 ✓ | yes (barely) 0.1 0.2 0.7 | 1 0 0 ✗ | no (way off)
Classifier B — confidently correct
Computed | Target | Correct? 0.1 0.2 0.7 | 0 0 1 ✓ | yes (confident) 0.1 0.7 0.2 | 0 1 0 ✓ | yes (confident) 0.3 0.4 0.3 | 1 0 0 ✗ | no (barely off)
Classification error is blind to how confident the prediction was. ACE is not — it uses ln() to reward confident correct predictions and heavily penalize wrong ones.
$$ACE = -\dfrac{1}{n}\sum_i \ln\bigl(\hat{y}_{\text{correct},i}\bigr)$$
For each example, only the log-prob of the TRUE class is counted
(other terms multiply by 0 from one-hot target and vanish)

Classifier A: −(ln(0.4)+ln(0.4)+ln(0.1))/3
   = −(−0.916 + −0.916 + −2.303)/3 = 1.38 ← higher = worse

Classifier B: −(ln(0.7)+ln(0.7)+ln(0.3))/3
   = −(−0.357 + −0.357 + −1.204)/3 = 0.64 ← lower = better ✓
ACE correctly identifies Classifier B as superior. Classification error cannot.
MSE for Classifiers — Better Than Accuracy, Still Worse Than ACE
$$\text{MSE} = \dfrac{1}{n}\sum_i \sum_j (y_{ij} - \hat{y}_{ij})^2 \quad \text{(summed over all output neurons)}$$
Clf A, ex1: (0.3−0)²+(0.3−0)²+(0.4−1)² = 0.09+0.09+0.36 = 0.54
Clf A, ex3: (0.1−1)²+(0.2−0)²+(0.7−0)² = 0.81+0.04+0.49 = 1.34
MSE Clf A = (0.54+0.54+1.34)/3 = 0.81

Clf B, ex1: (0.1−0)²+(0.2−0)²+(0.7−1)² = 0.01+0.04+0.09 = 0.14
Clf B, ex3: (0.3−1)²+(0.4−0)²+(0.3−0)² = 0.49+0.16+0.09 = 0.74
MSE Clf B = (0.14+0.14+0.74)/3 = 0.34
MSE also correctly ranks B above A, but it wastes signal on the wrong neurons — it penalizes the 0.3 and 0.4 outputs of the incorrect class, even though those are irrelevant to the decision. ACE only grades you on the probability you assigned to the true class, which is exactly the information that matters.
The Deeper Reason: MSE Causes Training to Stall Near Convergence
$$\Delta W \propto (\hat{y}-y)\cdot\underbrace{\hat{y}(1-\hat{y})}_{\sigma'(z)\text{ term}} \quad \text{(sigmoid + MSE)}$$
When ŷ̂ → 1.0 (confident & correct):  0.95·(1−0.95) = 0.0475
When ŷ̂ → 0.5 (uncertain):             0.5·(1−0.5)  = 0.25
As network improves, σ′(z) → 0 → gradient → 0 → weights barely move.
Training stalls even though not fully converged.
$$\Delta W \propto (\hat{y}-y) \quad \text{(cross-entropy + softmax/sigmoid \u2014 } \sigma'\text{ cancels!)}$$
Gradient ∝ prediction error only. No stalling. The cancellation is intentional.
  • This cancellation is why BCE is the canonical loss for binary classification with sigmoid output
  • The same cancellation occurs for CCE with softmax — ∂L/∂z = ŷ − y
  • This is not a coincidence — these loss-activation pairs are designed together to have clean gradients
What each loss punishes, and how hard
Cross-entropy in practice: the details that bite
  • Pass logits to the loss, never probabilities. CrossEntropyLoss and BCEWithLogitsLoss apply the softmax or sigmoid internally, fused with the log for numerical stability. Applying softmax yourself and then calling them means the activation is applied twice: the model still trains, worse, with quietly wrong gradients — a bug that produces mediocre results rather than an error
  • log(0) is −∞. Any hand-written cross-entropy needs its input clipped — log(max(p, 1e-7)) — or one confident mistake turns the whole batch's loss into NaN. The fused framework losses handle this; custom metric code usually does not
  • Label smoothing bounds the confidence. A hard target of 1 is only reachable by driving the correct logit infinitely far above the others, so cross-entropy keeps widening that gap forever and the model grows steadily more overconfident. Replace the target with 1 − ε and the optimum becomes finite. At ε = 0.1 over 10 classes the true class targets 0.9 and each other class 0.0111 — a calibration fix as much as a regulariser, and standard in transformer training
  • Focal loss reweights by difficulty. Multiplying by (1 − p_t)^γ suppresses examples the model already gets right: at γ = 2, an example at p_t = 0.9 contributes 1% of its unmodulated loss while one at 0.5 contributes 25%. Built for dense object detection at roughly 1000:1 background-to-object, where the sum of a million negligible easy-negative terms would otherwise swamp the informative ones
  • Class weights are the simpler answer for tabular imbalance. Focal loss is machinery aimed at extreme imbalance in deep models; for gradient-boosted trees, weighting the classes and then moving the decision threshold does the same job with fewer moving parts
the loss is not the metric

You train with cross-entropy and report accuracy, F1, or AUC. These are different objects with different jobs: the loss must be differentiable and informative about direction, the metric must be meaningful to whoever reads it. Accuracy is not differentiable, so it cannot be a training objective — its gradient is zero almost everywhere and undefined at the threshold.

The reverse mistake matters too: a falling loss and a flat metric is a real and common state. It usually means the model is becoming more confident about examples it already had right — which improves log loss and moves no predictions across the threshold. Watch both curves, and decide in advance which one gates the release.

Mistakes that survive code review
  • MSE for classification. It ranks classifiers correctly, so it looks defensible — and it wastes gradient on the non-target outputs and stalls as predictions sharpen, because σ′(z) → 0. Cross-entropy's cancellation exists precisely to avoid this
  • Double-applying softmax. Softmax in the model plus softmax inside the loss. Trains, badly, silently
  • MSE on a skewed target. Squared error fits the mean and a long tail drags it. Model log(y), or use Huber, or a Gamma/Tweedie objective — and remember that exponentiating a prediction of log(y) returns the median, not the mean
  • Unnormalised multi-task losses. Summing a loss of order 100 with one of order 0.01 means the second task is decoration. Normalise each by its scale, then weight deliberately — and re-check the weights when either task's data changes
  • Optimising a metric nobody wants. Accuracy on imbalanced data, or F1 when a miss costs a hundred times a false alarm. The optimiser will faithfully deliver whatever you asked for
  • Reading the training loss as progress. Training loss falls monotonically almost by construction. The validation curve is the one that carries information
  • Comparing losses across different reductions. A sum-reduced loss scales with batch size and a mean-reduced one does not, so "the loss went up" after a batch-size change is often just the reduction. Fix one convention
  • Ignoring that a weighted or resampled loss breaks calibration. Class weights, focal loss and resampling all shift the implied base rate on purpose. Ranking survives; probabilities need recalibrating before they are multiplied by anything
Where the choice of loss is the whole design
  • Focal loss made dense detection work. RetinaNet's contribution was largely the loss: at ~1000:1 background-to-foreground, the easy negatives dominate the gradient, and suppressing them let a single-stage detector match two-stage accuracy. A case where changing the loss, not the architecture, was the result
  • RLHF is a loss-function story end to end. Human preference pairs train a reward model under a Bradley–Terry pairwise objective — maximise log σ(r(preferred) − r(rejected)) — and that learned reward then becomes the objective for policy optimisation. The alignment problem is largely the problem of what to put in the loss
  • Contrastive losses built modern retrieval. InfoNCE and its variants pull matched pairs together and push mismatched ones apart, which is what makes CLIP, SimCLR and two-tower recommenders work. The loss defines the geometry of the embedding space, and that geometry is the product
  • Quantile loss where uncertainty is the deliverable. Demand planning, energy load, staffing: a point forecast is unusable and an interval is actionable, so the model is trained at several quantiles at once. Nothing about the architecture changes — only the loss
  • CTC for unaligned sequences. Speech and handwriting have targets that do not line up with inputs frame by frame. CTC marginalises over all alignments inside the loss, which removed the need for hand-aligned training data and reshaped the field
  • The pattern worth noticing: in every one of these, the loss encodes a structural fact about the problem — the imbalance, the preference ordering, the desired geometry, the uncertainty requirement, the missing alignment. Architecture search gets the attention; changing the objective is often the larger lever
🎯 In an interview

Lead with the likelihood framing. "Every loss encodes a noise assumption: squared error is Gaussian and fits the conditional mean, absolute error is Laplace and fits the median, cross-entropy is Bernoulli. So choosing a loss is choosing what statistic you want the model to predict." That single sentence answers a whole family of questions and sounds like modelling rather than recall.

Expect: "Why not MSE for classification?" — Two reasons, and give both. It spends gradient on the non-target outputs, which carry no information about the decision. And its gradient carries a σ′(z) = ŷ(1−ŷ) factor that collapses as predictions sharpen — 0.25 at ŷ = 0.5 but 0.0475 at ŷ = 0.95 — so training stalls exactly when the model is getting good. Cross-entropy with a sigmoid or softmax output cancels that factor exactly, leaving ∂L/∂z = ŷ − y, and that cancellation is by design, not luck.

Expect: "MSE, MAE, or Huber?" — Talk about gradients rather than loss values. MSE's per-example gradient grows with the error, so one point at error 100 outweighs a hundred points at error 1; MAE and Huber cap it. Huber is the default when unsure, and δ is the error size at which you stop trusting the point — so it lives in the target's units.

Volunteer the loss-versus-metric distinction: you train on cross-entropy and report AUC, because accuracy is not differentiable; and a falling loss with a flat metric usually means growing confidence on already-correct examples. Knowing that state exists is a strong signal of having actually watched training runs.

In code
Loss functions written out and their gradients checked numerically. The Huber and focal cases are the ones worth remembering — one for outliers, one for imbalance.
import numpy as np

y = np.array([1., 0., 1., 0.])
p = np.array([.9, .2, .4, .7])

# Binary cross-entropy: penalises confident mistakes without bound
bce = -np.mean(y*np.log(p) + (1-y)*np.log(1-p))
print("bce      ", round(bce, 4), "| grad wrt p:", np.round((p-y)/(p*(1-p))/len(y), 3))

# MSE on a classifier looks reasonable and trains badly: the gradient
# vanishes exactly where the model is most wrong (p near 0 or 1)
print("mse      ", round(np.mean((p - y)**2), 4))

# Huber: quadratic near zero, linear in the tail -> outliers stop dominating
def huber(r, delta=1.0):
    a = np.abs(r)
    return np.where(a <= delta, .5*r**2, delta*(a - .5*delta))
r = np.array([0.1, 0.5, 5.0, 50.0])
print("mse per-point  ", np.round(r**2, 1))          # 2500 from one outlier
print("huber per-point", np.round(huber(r), 1))      # 49.5 -- bounded influence

# Focal loss: down-weights the easy majority so the rare class is heard
def focal(y, p, gamma=2.0, alpha=.25):
    pt = np.where(y == 1, p, 1 - p)
    w = np.where(y == 1, alpha, 1 - alpha)
    return -np.mean(w * (1 - pt)**gamma * np.log(pt))
print("bce   ", round(bce, 4), " focal", round(focal(y, p), 4))
