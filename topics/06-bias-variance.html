Bias-Variance Tradeoff
The diagnostic framework that turns "my model is bad" into a specific next action. Test error splits into three parts, only two of which you can do anything about — and which one dominates tells you whether to reach for a bigger model or more data, because doing the wrong one makes things worse.
The decomposition, and what each term means
$$\mathbb{E}\big[(y - \hat{f}(x))^2\big] = \underbrace{\big(\mathbb{E}[\hat{f}(x)] - f(x)\big)^2}_{\text{bias}^2} + \underbrace{\mathbb{E}\big[(\hat{f}(x) - \mathbb{E}[\hat{f}(x)])^2\big]}_{\text{variance}} + \underbrace{\sigma^2}_{\text{irreducible}}$$
The expectation is over training sets, which is the part that makes this concrete. Imagine fitting the same model family on a hundred different samples from the same population:
  • Bias — how far the average of those hundred models sits from the truth. A systematic error the model family cannot express, no matter how much data you give it
  • Variance — how much the hundred models disagree with each other. Sensitivity to which particular rows you happened to draw
  • Irreducible noise — σ², the part of y that nothing in X can explain. No model beats this, and pretending otherwise is how people convince themselves they need a transformer
worked — fitting sin(x) a hundred times

Fit polynomials of increasing degree to 25 noisy points from sin(2πx), a hundred independent times each. Degree 1: bias² ≈ 0.22, variance ≈ 0.01 — every fit is a similar straight line, and every one is wrong the same way. Degree 15: bias² ≈ 0.01, variance ≈ 0.31 — each fit nails its own sample and they disagree wildly. The sum is minimised somewhere in the middle, and that middle is what "model selection" means.

High bias → underfitting
The model cannot represent the pattern. Both training and validation error are high, and — the diagnostic signature — they are close to each other.
  • Training error is already unacceptable
  • The gap to validation is small
  • More data does not help. This is the important part: more data reduces variance, and variance is not your problem
Fix by adding capacity: a more expressive model family, more or better features, interaction terms, less regularisation, longer training.
High variance → overfitting
The model memorised the sample. Training error is low, validation error is much higher, and the gap is the signal.
  • Training error near zero
  • Large train–validation gap
  • Performance swings noticeably between CV folds
Fix by constraining or averaging: more data, stronger regularisation, fewer features, a simpler family, early stopping, bagging, dropout.
Learning curves tell you which one you have
Plot training and validation error against training-set size. The shape answers the question directly, and takes minutes to produce.
What you seeDiagnosisDo this
Both high, converged togetherHigh biasAdd capacity. Do not buy more data
Low train, high val, gap still closingHigh varianceMore data will genuinely help
Low train, high val, gap flatHigh variance, saturatedRegularise or simplify — data has stopped paying
Val error rising with more dataDistribution shift or leakageStop tuning; check the split and the pipeline
That last row is worth internalising. Validation error getting worse as you add data is not a bias-variance phenomenon at all — it means your training and validation sets are drawn from different distributions, or a feature is leaking. No hyperparameter fixes it.
Bias-Variance tradeoff as model complexity increases
Where the classic curve stops being the whole story
The textbook U-shape says test error rises once you pass the interpolation point. Modern overparameterised networks do something else: error rises, peaks, and then falls again as capacity keeps growing — double descent.
A network with far more parameters than data points can fit the training set perfectly and still generalise, because gradient descent among the many perfect fits prefers smooth ones. The bias-variance decomposition is not wrong here — it is just that "variance" stops tracking parameter count once the model is heavily overparameterised and implicitly regularised.
how to hold both ideas

Use bias-variance as a diagnostic on the curves you measure, not as a prediction from parameter count. "Training error near zero and a large gap" still means overfitting whatever the model size. What changed is that "more parameters" is no longer reliable evidence of high variance.

Mistakes this framework is meant to prevent
  • Buying data to fix bias. If train and validation error are both high and close together, another million rows changes nothing. Plot the curve before you commission the labelling
  • Reading a single train/test number. One split gives you one draw from the variance distribution. High-variance models look great or terrible depending on the seed — which is precisely what cross-validation exists to reveal
  • Calling any gap "overfitting". A small, stable gap is normal and healthy. The question is whether validation error is still falling, not whether the gap is non-zero
  • Treating irreducible error as a failure. If the label genuinely is not determined by your features, you have hit σ². The honest move is to say so and go looking for new features — not to try a bigger architecture
  • Assuming more parameters means more variance. True for polynomials and trees, unreliable for heavily overparameterised networks. Measure the gap; do not infer it from a parameter count
  • Tuning on the test set. Every decision informed by test performance turns it into a validation set, and your final number becomes optimistic by an unknown amount
How this shows up in real work
  • Learning curves as a budget argument. "The gap has stopped closing, so more labelling will not pay — we need better features instead" is a far stronger case to a manager than a request for more data, and the curve is the evidence
  • Ensembling is a deliberate variance trade. Random forests spend compute to cut variance and accept the bias of shallow-ish trees; boosting does the opposite. Choosing between them is choosing which term you are attacking
  • Regularisation strength is the dial, and it is data-dependent. The right weight decay for 10,000 rows is wrong for 10 million. Retune it when your data volume changes materially — it is one of the few hyperparameters that genuinely must move
  • In credit and fraud, bias is often preferred. A slightly underfit monotonic model that behaves predictably out of sample can be worth more than a lower-error model that swings between retrains, because the downstream policy has to be stable
🎯 In an interview

Do not recite the definitions. Say what each one looks like on a curve: "high bias is both errors high and converged; high variance is a low training error with a large gap." Then say what you would do about each. That turns a memorised tradeoff into a diagnostic procedure.

Expect: "Your model has 95% training and 70% test accuracy. What do you do?" — Name it as variance, then give the ordered list: more data, then regularisation, then a simpler family, then early stopping. And check for leakage, because a 25-point gap is large enough to be suspicious.

Then: "What if both were 70%?" — Bias. More data is the wrong answer, and saying so explicitly is the point of the question.

Strong close: mention that the expectation in the decomposition is over training sets, and that double descent means parameter count is no longer a proxy for variance. Both signal you have read past the textbook.

In code
The decomposition made concrete: fit the same model family at increasing capacity and watch bias fall while variance climbs. The U-shape in test error is the whole lesson.
import numpy as np
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import make_pipeline

rng = np.random.default_rng(0)
f = lambda x: np.sin(2 * np.pi * x)
x_test = np.linspace(0, 1, 200)

for degree in [1, 3, 9, 15]:
    preds = []
    for _ in range(100):                     # 100 independent training sets
        x = rng.uniform(0, 1, 25)
        y = f(x) + rng.normal(0, 0.3, 25)
        m = make_pipeline(PolynomialFeatures(degree), LinearRegression())
        preds.append(m.fit(x[:, None], y).predict(x_test[:, None]))
    P = np.array(preds)

    bias2 = ((P.mean(0) - f(x_test)) ** 2).mean()   # avg model vs truth
    var   = P.var(0).mean()                          # spread across datasets
    print(f"degree {degree:2d}   bias^2={bias2:.4f}  variance={var:.4f}  "
          f"sum={bias2 + var:.4f}")
