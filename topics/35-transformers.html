Transformers
Attention explains why the architecture works. This topic is about what it costs to build and serve one — because every design choice that distinguishes a 2017 transformer from a 2024 one is a response to an arithmetic problem: attention is quadratic in sequence length, the KV cache can exceed the model itself, and the naive implementation is bound by memory bandwidth rather than compute.
The block, and where its parameters go
A transformer layer is two sublayers, each wrapped in a residual connection and a normalisation. That is the whole architecture — the depth comes from stacking it.
$$\begin{aligned} x &\leftarrow x + \text{MHA}\big(\text{LN}(x)\big) \\ x &\leftarrow x + \text{FFN}\big(\text{LN}(x)\big) \end{aligned}$$
Note the normalisation sits inside the residual branch — pre-norm, which is what every modern model uses. The original paper put it after the addition (post-norm), and that turned out to need careful warmup to train at depth, because the residual path no longer had a clean identity route. Pre-norm leaves the skip connection untouched, so the gradient path multiplies by exactly 1. It is a one-line change that made deep stacks trainable without heroics.
Counting the parameters is worth doing once, because it tells you where a model's capacity actually lives. With model width d, attention holds four d × d projections (Q, K, V, and the output), and the feed-forward network expands to 4d and back:
ComponentParametersShare
Attention — Q, K, V, O projections4d²1/3
Feed-forward — d → 4d → d8d²2/3
Per layer12d²
Two thirds of a transformer is the feed-forward network, not attention. That surprises people, and it explains why mixture-of-experts targets the FFN specifically — it is where the parameters are. At d = 4,096 that is 201M parameters per layer, so 32 layers gives 6.4B, which lands about where a "7B" model does once embeddings are included. Being able to do that estimate in your head is genuinely useful for judging whether a claimed configuration is plausible.

The quadratic, and what it costs in memory
Attention compares every position with every other, so both compute and the attention matrix itself scale with T². The compute cost is discussed often; the memory cost is what actually broke things.
$$\text{scores} = \frac{QK^{T}}{\sqrt{d_k}} \in \mathbb{R}^{T \times T} \qquad\Longrightarrow\qquad \text{one matrix per head, per layer}$$
At T = 4,096, fp16Memory
one attention matrix (4,096²)33.6 MB
× 32 heads, one layer, one sequence1.07 GB
A single layer's attention scores for one sequence exceed a gigabyte. Multiply by batch size and it becomes the binding constraint — and note that this matrix is written to memory and then immediately read back by the softmax, so the operation is bound by memory bandwidth, not by arithmetic.
That observation is what FlashAttention exploits. It never materialises the T × T matrix at all: it processes the scores in tiles that fit in on-chip SRAM, computing the softmax incrementally with a running maximum and normaliser. The FLOP count is unchanged — it is not a cheaper algorithm — but the memory traffic drops by an order of magnitude and memory is what the operation was waiting on. Attention memory goes from O(T²) to O(T), which is why long contexts became affordable without changing the maths at all.
The scaling is brutal and worth internalising: going from 2,048 to 8,192 tokens is 4× the context and 16× the attention work. Everything marketed as "long context" is a strategy for avoiding paying that in full — sparse or windowed patterns, linear approximations, or FlashAttention-style exact methods that fix the memory term while leaving the compute term quadratic.
The KV cache: why serving is a different problem from training
Generation is autoregressive, so producing token t requires attending over tokens 1…t−1. Recomputing their keys and values every step would be O(T²) work per sequence, so you cache them. That cache is the central object in inference engineering, and its size surprises people.
$$\text{KV bytes} = 2 \times L \times H_{kv} \times d_{head} \times T \times \text{bytes}$$
For a 7B-class model — 32 layers, 32 heads, head dimension 128 — in fp16:
SettingKV cache at T = 4,096
One sequence, full multi-head attention2.1 GB
Batch of 32 sequences68.7 GB — larger than the 14 GB of weights
Grouped-query attention, 8 KV heads537 MB — a 4× reduction
Multi-query attention, 1 KV head67 MB — a 32× reduction
At batch 32 the cache is nearly five times the model. That single fact reshaped inference: throughput is limited by how many sequences fit in memory alongside their caches, not by arithmetic. It is why grouped-query attention is now standard — let several query heads share one key/value head, keeping most of the quality while cutting the cache proportionally. It is also why paged attention exists: the cache is managed like virtual memory, in fixed blocks, to avoid the fragmentation that comes from pre-allocating for the longest possible sequence.
the asymmetry that explains inference cost

Prefill — processing the prompt — handles all T tokens at once, so it is compute-bound and parallel, and it is what you pay for a long prompt. Decode — generating each subsequent token — processes exactly one token against the whole cache, so it is memory-bandwidth-bound and inherently serial.

These have completely different bottlenecks, which is why time-to-first-token and tokens-per-second are separate metrics that respond to different optimisations, and why batching helps decode enormously (it amortises the weight reads across sequences) while doing much less for prefill. If someone reports "latency" for a language model without saying which phase, the number means very little.

Position: from sinusoids to rotation
Attention is a sum over positions, and sums do not care about order — permute the input and the output permutes identically. A transformer with no positional information cannot distinguish "dog bites man" from "man bites dog". Position has to be injected deliberately.
$$PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{2i/d}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d}}\right)$$
The original sinusoidal scheme adds a fixed pattern of many frequencies to the embeddings. Its appeal was that relative offsets are expressible as linear functions of the encoding, so the model can in principle learn "attend three positions back". Its weakness is that it is added to the input, so the information has to survive every layer.
SchemeMechanismTrade-off
Sinusoidalfixed pattern added to embeddingsno parameters, no training limit — but weak extrapolation in practice
Learned absolutea trainable vector per positionsimple, and hard-capped at the trained length. BERT's 512 limit is this
RoPErotates Q and K by an angle proportional to positionthe modern default — relative by construction, and the rotation can be interpolated to extend context
ALiBiadds a distance-proportional penalty to attention scoresextrapolates naturally to longer sequences than trained on
Rotary embeddings won for a structural reason. They act on the queries and keys inside every attention operation rather than on the input once, so position cannot be diluted with depth. And because position is encoded as a rotation angle, you can scale the angles down to stretch a model trained at 4K to a longer context — which is exactly what the "context extension" techniques do. That is not available to a learned absolute table, where position 8,192 simply has no vector.

What changed since 2017
The 2017 block and a current one differ in half a dozen places, and every change has a reason worth knowing rather than a name to memorise.
2017NowWhy

Read the "why" column as a group and a pattern emerges: almost none of these improve the model's expressiveness. They make it trainable at depth, cheaper to serve, or able to handle longer sequences. The 2017 architecture was close to right; nearly everything since has been engineering around its costs.

Mistakes that survive code review
  • Forgetting the causal mask in a decoder. Every position attends to the future, so the model learns to read the answer off the input. Training loss collapses to near zero and generation is incoherent — one of the most memorable bugs in the field precisely because the loss curve looks spectacular
  • Forgetting the padding mask. Attention over pad tokens injects noise, and it is silent. Both masks are required and they are different things
  • Assuming a bidirectional encoder can generate. BERT-style models see the whole sequence, so they cannot produce tokens left to right. Encoder-only for understanding, decoder-only for generation — this is architectural, not a matter of tuning
  • Exceeding the positional limit. A learned absolute table has no vector for a position beyond training, so behaviour past the limit is undefined rather than merely degraded. Check what scheme the model uses before assuming a context window is soft
  • Reasoning about cost from parameter count alone. Inference is dominated by the KV cache and memory bandwidth, not by weight count — a batch of 32 at 4K context carries more cache than model
  • Quoting one latency number. Prefill is compute-bound and parallel; decode is bandwidth-bound and serial. They optimise differently and must be reported separately
  • Expecting attention weights to be an explanation. They show where the model looked, which is not why it decided. Attention maps are appealing and weak evidence — the literature on this is explicit
  • Fine-tuning without matching the pretraining format. Tokeniser, special tokens, prompt template. A mismatch degrades quality in ways that look like a data problem
  • Treating a long context window as usable throughout. Models attend unevenly across a long context and reliably degrade in the middle. The advertised window is a capacity, not a guarantee of uniform attention
How they are actually built and served
  • Decoder-only won by convergence, not by proof. One stack, one objective, and scaling that generalises — encoder-decoder survives where input and output are genuinely different modalities (translation, speech), and encoder-only survives for retrieval and classification where you want a representation rather than a continuation
  • Serving is a memory-management discipline. Continuous batching keeps the GPU fed by admitting new sequences as others finish; paged attention manages the KV cache in fixed blocks to avoid fragmentation; quantisation shrinks both weights and cache. None of this changes the model — it changes how many users one machine serves, which is the number that matters commercially
  • Mixture of experts is how parameter counts grew without proportional cost. Route each token to a small number of expert FFNs and total parameters rise while per-token compute stays roughly flat. The difficulty is engineering rather than modelling: load balancing across experts, and the fact that all experts must be resident in memory even though each token uses few
  • Long-context claims deserve reading closely. Extending a trained model's context by interpolating RoPE angles works, and quality across the window is uneven. The honest question about any long-context model is not whether it accepts the tokens but whether retrieval accuracy holds in the middle
  • The transferable lesson: the architecture stopped being the interesting variable around 2020. What changed since is data, scale, and the serving stack — which is why an engineer who understands the KV cache and batching is often more useful on a production LLM team than one who can recite the block diagram
🎯 In an interview

Know where the parameters are. "Per layer it is 4d² for attention and 8d² for the feed-forward network, so two thirds of a transformer is the FFN — which is why mixture-of-experts targets it. At d = 4,096 that is 201M per layer, so 32 layers is about 6.4B." Most candidates assume attention dominates, and the estimate itself is a useful skill.

Expect: "Why is long context hard?" — Answer with memory rather than FLOPs, because that is where the real constraint is. The T × T score matrix at 4K with 32 heads is 1.07 GB for one sequence in one layer, and the operation is bandwidth-bound. FlashAttention keeps the same FLOPs and tiles the computation so the matrix is never materialised — O(T) memory instead of O(T²). And 2K → 8K is 4× the context for 16× the attention work.

The answer that signals production experience: the KV cache. For a 7B model at 4K context it is 2.1 GB per sequence — at batch 32, 68.7 GB, nearly five times the 14 GB of weights. That is why grouped-query attention is standard (8 KV heads instead of 32 cuts it 4×) and why paged attention exists. Follow with the prefill/decode asymmetry: compute-bound and parallel versus bandwidth-bound and serial, so batching helps one far more than the other.

Expect: "Why RoPE over sinusoidal or learned?" — It rotates Q and K inside every attention operation rather than adding to the input once, so position cannot dilute with depth, and it is relative by construction. Crucially the angles can be interpolated to extend context beyond the trained length, which a learned absolute table cannot do because position 8,192 has no vector. Do not say attention weights explain the model's decision, and do not quote a single latency number.

In code
A full pre-norm transformer block. The two details that matter in practice are the residual placement and where the parameters actually live — the FFN, not attention.
import torch, torch.nn as nn

class Block(nn.Module):
    """Pre-norm block, as used by GPT-2 onward. Post-norm (the 2017 paper)
    needs learning-rate warmup to train at depth; pre-norm mostly does not."""
    def __init__(self, d_model=768, n_heads=12, mlp_ratio=4, p=0.1):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = nn.MultiheadAttention(d_model, n_heads, dropout=p, batch_first=True)
        self.ln2 = nn.LayerNorm(d_model)
        self.mlp = nn.Sequential(nn.Linear(d_model, mlp_ratio*d_model),
                                 nn.GELU(),
                                 nn.Linear(mlp_ratio*d_model, d_model),
                                 nn.Dropout(p))
    def forward(self, x, mask=None):
        h = self.ln1(x)
        x = x + self.attn(h, h, h, attn_mask=mask, need_weights=False)[0]
        x = x + self.mlp(self.ln2(x))        # residual around each sublayer
        return x

blk = Block()
x = torch.randn(2, 128, 768)
causal = torch.triu(torch.ones(128, 128, dtype=torch.bool), diagonal=1)
print("out", blk(x, mask=causal).shape)

# Where the parameters are: the FFN holds twice what attention does
attn_p = sum(p.numel() for p in blk.attn.parameters())
mlp_p  = sum(p.numel() for p in blk.mlp.parameters())
print(f"attn {attn_p/1e6:.2f}M   mlp {mlp_p/1e6:.2f}M   ratio {mlp_p/attn_p:.1f}x")
# 12 layers of this is roughly GPT-2 small (124M with embeddings)
