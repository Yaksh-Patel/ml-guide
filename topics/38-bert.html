BERT & Encoder Models
BERT's bet was that understanding needs to see both directions at once, so it gave up the ability to generate in exchange for it. The bet was right for its tasks and it cost BERT the future, because the objective that enables bidirectionality also throws away most of its training signal. Both halves of that trade are worth understanding — encoder models are still the correct tool for retrieval and classification, and the reason they stopped scaling is the more interesting lesson.
Masked language modelling, and the 80/10/10 rule
An autoregressive model predicts the next token, which means it must never see the future — so it is inherently one-directional. BERT wants both directions, so it cannot predict the next token; instead it corrupts the input and reconstructs it. Bidirectionality falls out for free, because a masked position can be inferred from either side.
The corruption recipe is oddly specific and every part of it has a reason. 15% of tokens are selected, and of those:
Share of selectedReplacementWhy
80% (= 12% of all tokens)[MASK]the actual prediction task
10% (= 1.5%)a random tokenforces the model to use context even when a real-looking token is present — otherwise it would learn "only distrust [MASK]"
10% (= 1.5%)left unchangedkeeps the representation of genuine tokens honest, since the model must still predict them correctly
The reason for the mixture is a train/serve mismatch. [MASK] never appears at fine-tuning or inference time — real inputs have no masks. If pretraining only ever asked the model to fill in [MASK], it would learn a skill it can never use again, and its representations of ordinary tokens would go unsupervised. The 10% random and 10% unchanged cases force it to build useful representations of every position, not just the marked ones.
Next-sentence prediction was the second objective: given two segments, classify whether the second followed the first. RoBERTa later showed that removing it improves results — the task is close to trivial, since a random second segment usually comes from a different document and is detectable on topic alone, so the model learned topic matching rather than discourse coherence. Its main legacy is the [CLS] token, which is why [CLS] makes such a poor sentence embedding: the only thing that ever supervised it was a task it could solve without understanding much.
Attention masks: the whole encoder-vs-decoder distinction
The hidden cost: 15% signal
Here is the trade that decided the architecture's future, and it is one division.
Training signal per sequence
Autoregressive (GPT-style)every position predicts the next token — 100% of tokens produce a loss term
Masked (BERT-style)only the masked positions are predicted — 15% of tokens
Both models do a full forward and backward pass over the whole sequence. The autoregressive one extracts a prediction from every position; BERT throws away 85% of the possible supervision. Per unit of compute and per token of data, masked modelling is roughly 6.7× less sample-efficient in signal terms.
That is a large part of why decoder-only models scaled and encoder-only models did not. When data and compute are the binding constraints, an objective that uses every token wins — and it happens to give you generation for free, whereas bidirectionality buys accuracy on tasks you could also solve by fine-tuning a decoder. BERT was not out-competed on understanding; it was out-competed on scaling economics. Knowing that distinction is the point of this topic.
and it still cannot generate — architecturally, not by degree

Bidirectional attention means every position sees every other, including later ones. To generate left-to-right you must not see the future, so there is no ordering in which BERT can emit tokens: producing token 5 requires attending to tokens 6 onward, which do not exist yet.

This is not "BERT generates poorly" — it is that the forward pass is not defined for the task. Encoder-only for classification, extraction and embeddings; decoder-only for generation; encoder-decoder when input and output are genuinely different sequences.

The architecture, and checking the parameter count
BERT is a transformer encoder stack with a learned positional table and two special tokens. Its sizes are worth being able to reconstruct rather than recall, using the 12d²-per-layer rule:

The estimate lands within 2% — the remainder is biases, LayerNorm parameters, the 512 × d positional table and the pooler. Note that the embedding matrix is 22% of BERT-base, which is why ALBERT's factorised embeddings were an effective size reduction and why vocabulary size is a real architectural decision rather than a detail.
the 512-token limit is a hard wall, not a soft one

BERT uses a learned absolute positional embedding table with 512 rows. Position 512 has no vector — not a degraded one, none. So the limit is not a performance guideline, it is the edge of the model's domain, and this is exactly the contrast with rotary embeddings, whose angles can be interpolated to extend context.

Longer documents must be chunked with overlap, or handled by an architecture built for it (Longformer's sparse attention, or a model with relative positions). Silently truncating at 512 removes the end of every long document, and the resulting accuracy ceiling looks like a data problem.

Mistakes that survive code review
  • Reaching for BERT to generate text. Bidirectional attention makes autoregressive decoding undefined, not merely bad
  • Raw [CLS] as a sentence embedding. It was supervised only by next-sentence prediction. Mean-pool the token states, or use a model trained with a similarity objective
  • One high learning rate across all layers. Pretrained representations are the asset you are trying to keep; a large global rate overwrites them in the first few hundred steps. Low rate for early layers, higher for later ones, highest for the fresh head
  • Assuming 512 characters means 512 tokens. Specialised vocabulary tokenises densely. Measure the distribution of your actual corpus through the actual tokeniser
  • Base BERT on specialised text. Wikipedia and BookCorpus do not cover clinical or legal vocabulary, so those terms fragment into meaningless pieces. Use a domain checkpoint, or continue MLM pretraining on your own corpus before task fine-tuning — that intermediate step is reliably worth its cost
  • Forgetting to mask padding when mean-pooling. Averaging over pad positions drags every embedding toward the pad token's representation, and it varies with batch composition
  • Fine-tuning on a few hundred examples and expecting stability. Small-data BERT fine-tuning is notoriously seed-sensitive — different seeds give materially different results. Run several and report the spread, or freeze more of the model
  • Choosing BERT-base by default. RoBERTa is the same architecture trained properly and is a strictly better starting point; DeBERTa is better again on understanding benchmarks. There is rarely a reason to start from original BERT except reproducing a paper
  • Treating a cross-encoder as interchangeable with a bi-encoder. A cross-encoder scores pairs, so it cannot be pre-indexed. Excellent for reranking a shortlist, unusable for first-pass retrieval
How It's Used at Top Companies
  • Google (Search, 2019): BERT deployed in Google Search for query understanding — the most impactful change to Google Search in 5 years at announcement; used to understand long-tail, conversational, and preposition-heavy queries where word order matters
  • LinkedIn (content relevance): RoBERTa fine-tuned for feed post relevance scoring; used to rank which posts appear in each user's feed based on semantic relevance to their professional interests
  • Amazon (product search): bi-encoder with BERT backbone for product retrieval; query and product title encoded separately, similarity at serving time — BERT's contextual representations outperform TF-IDF for long-tail product queries
  • Healthcare NLP (ClinicalBERT): BERT fine-tuned on clinical notes for entity extraction (medications, diagnoses, procedures) and de-identification — contextual embeddings handle medical abbreviations and domain jargon far better than rule-based NER
🎯 In an interview

State the trade, both directions. "BERT masks 15% of tokens and reconstructs them, which buys bidirectional context — every position sees left and right. The cost is that only 15% of positions produce a training signal, where an autoregressive model gets one from every token. That is roughly 6.7× less signal per sequence, and it is a large part of why decoder-only models scaled and encoder-only models did not." Very few candidates give the cost side, and it is the more interesting half.

Expect: "Why the 80/10/10 split?" — Because [MASK] never appears at fine-tuning time. If pretraining only asked the model to fill masks, it would learn a skill it can never use and leave representations of ordinary tokens unsupervised. The 10% random forces context use even when a plausible token is present; the 10% unchanged keeps real-token representations honest. Getting this right signals you have read the paper rather than a summary.

Expect: "BERT versus RoBERTa?" — RoBERTa is BERT trained properly: much more data, no NSP (it was found to hurt), dynamic masking rather than one fixed mask per example, larger batches, longer training. Same architecture, better recipe — which is itself the useful observation, because it means the original result was compute-limited rather than design-limited.

Volunteer two things. That the 512-token limit is a learned positional table with no row for position 512, so it is a hard wall rather than a soft degradation — and contrast with RoPE, whose angles interpolate. And that encoder models are still correct for retrieval, reranking and classification at scale, because you want one forward pass and a fixed-size vector rather than generation. Do not say BERT "generates poorly".

In code
Masked language modelling set up by hand — the 80/10/10 corruption rule is the part people misremember — plus the pooling choice that decides sentence-embedding quality.
import torch
from transformers import AutoTokenizer, AutoModel

tok = AutoTokenizer.from_pretrained('bert-base-uncased')
model = AutoModel.from_pretrained('bert-base-uncased')

# MLM corruption: of the 15% chosen positions, 80% become [MASK],
# 10% become a random token, 10% are left alone. The last two exist so the
# model cannot assume "a token I must predict is always [MASK]" -- fine-tuning
# never shows it a [MASK] at all.
def corrupt(ids, mask_id, vocab_size, p=0.15, gen=None):
    labels = ids.clone()
    sel = torch.rand(ids.shape, generator=gen) < p
    labels[~sel] = -100                                   # ignored by the loss
    r = torch.rand(ids.shape, generator=gen)
    ids[sel & (r < 0.8)] = mask_id
    rnd = sel & (r >= 0.8) & (r < 0.9)
    ids[rnd] = torch.randint(vocab_size, (int(rnd.sum()),))
    return ids, labels

batch = tok(["the model learns from context", "encoders see both directions"],
            return_tensors='pt', padding=True)
out = model(**batch).last_hidden_state
print("hidden", out.shape)                                # [2, T, 768]

# Sentence embedding: MEAN POOLING over real tokens beats [CLS] unless the
# model was explicitly trained with a [CLS] objective (SBERT does this).
m = batch['attention_mask'].unsqueeze(-1)
mean_pooled = (out * m).sum(1) / m.sum(1)                  # mask out padding
cls = out[:, 0]
print("mean", mean_pooled.shape, "| cls", cls.shape)
# Encoder-only: bidirectional, great for classification/NER/retrieval,
# cannot generate. That is the whole BERT-vs-GPT distinction.
