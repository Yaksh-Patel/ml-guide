Gradient Boosting
The idea that a long sequence of deliberately mediocre models, each one looking only at what its predecessors got wrong, beats a single strong model. It has held the top of tabular prediction for a decade. The reason is the direction it attacks error from: Random Forest averages away variance, boosting grinds down bias — and almost every practical difference between them follows from that one fact.
It is gradient descent, but the parameter is the function
"Each tree fits the previous trees' residuals" is true and it hides the actual idea. Ordinary gradient descent improves a model by nudging its parameters down the loss gradient. Boosting nudges the predictions themselves:
$$\theta \leftarrow \theta - \eta\,\frac{\partial L}{\partial \theta} \qquad\text{versus}\qquad F(x) \leftarrow F(x) - \eta\,\frac{\partial L}{\partial F(x)}$$
The second update wants to move a whole function, and you cannot store an arbitrary function — so you fit a small tree to approximate the gradient and add that instead. The tree is not the model; the tree is one step of gradient descent. Everything else is bookkeeping:
$$r_{im} = -\left[\frac{\partial L(y_i, F(x_i))}{\partial F(x_i)}\right]_{F=F_{m-1}} \qquad F_m(x) = F_{m-1}(x) + \eta\, h_m(x)$$
where rim is the pseudo-residual for row i at round m, hm is the tree fitted to those pseudo-residuals, and η is the learning rate. Now the "residuals" story becomes a special case rather than the definition:
  • Squared loss L = ½(y − F)² gives ∂L/∂F = −(y − F), so the negative gradient is the plain residual. This is the only loss for which the folklore is literally true
  • Log loss gives a negative gradient of y − σ(F): the residual in probability space, not in log-odds space. The trees are fitted on a different scale from the one they are added on
  • Absolute error gives sign(y − F) — just ±1. The tree learns which direction to move each row, not how far, which is exactly why MAE-boosting is robust to outliers
This is why any differentiable loss can be boosted — ranking objectives, Poisson counts, quantiles, Tweedie for insurance claims. You supply a gradient; the machinery is unchanged.

Read down the residual column: every entry is exactly half the one above it. That is not a coincidence of these numbers — take a fraction η of a correction and (1 − η) of the error survives. The error decays geometrically at rate (1 − η), and that single fact is what makes the learning rate predictable.
the caveat that makes this honest

A real depth-3 tree has at most 8 leaves and must give every row in a leaf the same output, so it captures only part of the residual pattern — never all of it. That is deliberate: a tree flexible enough to fit the residual vector exactly would drive training error to zero in one round and generalise nothing. The weakness of the base learner is a feature. It is also why real models need hundreds or thousands of rounds where this table needed four.

The learning rate, and the trade it forces
Since a fraction (1 − η) of the error survives each round, you can compute how many rounds you need. To remove 95% of the initial error, solve (1 − η)m ≤ 0.05:
$$m \ \ge\ \frac{\ln 0.05}{\ln(1-\eta)}$$

The product is nearly constant, which is the practical rule: η and n_estimators are one parameter wearing two hats. Halve the learning rate and you need roughly twice the trees for the same fit. So there is no point tuning them jointly on a grid — fix η at 0.05 or 0.1, set n_estimators generously, and let early stopping find the count.
Why small η generalises better, given the same final fit. Each tree is fitted to the residual as it stands at that moment, so with a small η the ensemble takes many small steps and every tree sees a slightly different, still-noisy target. The result is closer to an average over many weak corrections than to a short sequence of confident ones. Large η lets a single tree — including a single tree that latched onto noise — move the ensemble a long way with nothing following it to compensate. Shrinkage is the most reliable regulariser boosting has, and it is why the default is small and the tree count is large.

the noise sensitivity nobody mentions

Boosting works by attending to whatever is still wrong, so a mislabelled row is a row it can never satisfy — and its gradient stays large while everything else shrinks. Round after round the ensemble devotes more capacity to explaining a mistake in your data. Bagging has the opposite reflex: a bad row appears in ~63% of trees and gets averaged down. On a dataset you suspect is noisily labelled, a forest is the safer default, and boosting needs its regularisation taken seriously — subsampling, higher min_child_weight, and a loss like Huber or MAE that refuses to chase a single point.

Early stopping, and the trap inside it
Because more rounds eventually overfit, the tree count is not a hyperparameter you guess — it is one you read off a validation curve. Set n_estimators high, pass an evaluation set, stop when the metric has not improved for early_stopping_rounds.
The diagnostic is unusually legible: training loss falls monotonically forever while validation loss falls, flattens, and turns back up. The turn is the round to keep. A forest cannot produce this curve, which is the clearest practical demonstration that the two methods fail in different directions.
the number you then report is not honest

You chose the tree count by looking at the validation set, so that set has been selected on — its score is optimistically biased in exactly the way a tuned hyperparameter always biases the data it was tuned on. Early stopping is model selection, and it needs the same discipline as any other model selection.

Use three splits, not two: train, an early-stopping set, and a test set touched once. Or nest it — early-stop inside each outer CV fold. Reporting the early-stopping set's score as the model's performance is one of the most common ways a boosted model looks better in a notebook than in production, and it is invisible unless you go looking.

XGBoost
  • Second-order (Hessian) expansion, so leaf values have a closed form
  • Regularisation written into the objective — γ per leaf, λ on leaf weights
  • Level-wise growth: expands a whole depth at a time, which is implicitly conservative
  • Learns a default direction for missing values
  • The reference implementation; monotone constraints make it the regulated-industry choice
Gold standard
LightGBM
  • Leaf-wise growth: splits the single highest-gain leaf anywhere in the tree, so trees go deep and lopsided. More gain per tree, and easier to overfit — control with num_leaves and min_data_in_leaf, not max_depth
  • GOSS keeps the large-gradient rows and samples the rest, since small-gradient rows are already fitted
  • EFB bundles mutually exclusive sparse features into one column
  • Often 10× faster on large data at comparable accuracy — the default above a few hundred thousand rows
Speed king
CatBoost
  • Ordered target statistics: encodes a category using only rows that came earlier in a random permutation
  • That ordering exists to kill a real leak — plain target encoding lets a row's own label into its own feature, which inflates CV and collapses in production
  • Ordered boosting applies the same trick to the gradients themselves
  • Symmetric trees: weaker per tree, very fast at inference
  • The right default when raw high-cardinality categoricals dominate

Mistakes that survive code review
  • Grid-searching n_estimators. Redundant with early stopping and expensive. It also signals not knowing the tool, which in an interview costs more than the compute
  • Reporting the early-stopping set's score. That set chose the tree count, so it is contaminated. Keep a third split, or nest the early stopping inside CV
  • Tuning η and n_estimators jointly. Their product is roughly fixed. Two parameters, one degree of freedom, and a grid that wastes most of its budget
  • Bringing forest habits. Deep trees are right for a forest and wrong here — boosting reduces bias, so it wants high-bias base learners. Depth 12 in XGBoost is usually a bug
  • Preprocessing outside the pipeline. Any imputer or scaler fitted before the split leaks into the early-stopping set, which then picks the wrong round for the wrong reason. Everything inside a Pipeline
  • Boosting hard on noisily labelled data. The algorithm chases what it cannot fit. Check for label noise before blaming the hyperparameters, and consider a forest or a robust loss
  • Shuffled CV on temporal data. Boosting's capacity makes it exceptionally good at exploiting a leak. A shuffled split on time-ordered data produces a beautiful score and a worthless model
  • Trusting the probabilities after scale_pos_weight. You deliberately changed the implied base rate. Fine for ranking; recalibrate before anything is multiplied by money
  • Forgetting the seed. Row and column subsampling are random, so runs differ. Set it, or you cannot tell a real improvement from a reseed
Why it still owns tabular data
  • It wins the benchmark that matters and keeps winning. On heterogeneous tabular data — mixed types, missing values, non-linear interactions, a few hundred columns — boosted trees still match or beat deep learning while training in minutes on a CPU. Repeated head-to-head studies find the same thing, which is why the "just use a neural net" advice never took over this domain
  • Ad and content ranking. CTR and relevance models run boosted trees on sparse categorical features at single-digit-millisecond latency and billions of daily calls. Inference is a few hundred short tree traversals — cheap, predictable, and easy to serve
  • Fraud and risk, with the temporal discipline attached. The standard pattern is training on a time window, early stopping on the following slice, and testing on the one after that, because a fraud model validated on shuffled data always looks excellent. Retraining is scheduled, not occasional
  • Credit scoring with monotone constraints. This is the feature that got boosting past model risk review: you can force the score to move monotonically with income or utilisation, so the model is auditable in the direction regulators care about, and SHAP supplies the per-applicant reasons. It is how a non-linear model became acceptable where scorecards used to be mandatory
  • Where it is the wrong tool: anything needing extrapolation beyond the training range (it inherits the tree staircase in full), genuine perceptual data — images, audio, raw text — and very wide sparse problems where a linear model is both faster and better
🎯 In an interview

Lead with the gradient-descent framing. "Boosting is gradient descent in function space — each tree approximates the negative gradient of the loss with respect to the current predictions, and you add a fraction η of it. For squared loss that gradient is the residual, which is why the residual story works; for log loss it is y − σ(F)." That answer immediately covers "why does it work with any loss function", which is the usual follow-up.

Expect: "Boosting versus bagging." — Do not list properties; give the cause. Bagging fits independent trees and reduces variance, so it wants deep low-bias trees and cannot overfit by adding more. Boosting fits sequentially and reduces bias, so it wants shallow high-bias trees and must be early-stopped. Every other difference — parallelism, tuning effort, noise sensitivity — follows from that.

Expect: "How do you choose the learning rate?" — Show you know it is not independent: error decays like (1 − η) per round, so η × n_estimators is roughly constant. Fix η small, set the tree count high, early-stop. Then volunteer the part most people miss — the early-stopping set has been selected on, so an honest number needs a third split.

The differentiator: mention that boosting is sensitive to label noise because it keeps escalating attention on rows it cannot fit, while bagging averages them away. Almost nobody says this, and it demonstrates you have debugged a boosted model rather than only tuned one.

In code
Gradient boosting in fifteen lines, so the "fit the next tree to the residual" claim stops being a slogan. The final loop shows the learning-rate / n_estimators trade.
import numpy as np
from sklearn.tree import DecisionTreeRegressor
from sklearn.metrics import mean_squared_error

rng = np.random.default_rng(0)
X = rng.uniform(-3, 3, (500, 1))
y = np.sin(X[:, 0]) + 0.2 * rng.normal(size=500)

# Boosting from scratch: each tree fits the gradient of the loss so far.
# For squared error the gradient IS the residual, which is the whole trick.
pred = np.full_like(y, y.mean())
trees, lr = [], 0.1
for _ in range(200):
    residual = y - pred                       # negative gradient of MSE/2
    t = DecisionTreeRegressor(max_depth=3).fit(X, residual)
    pred += lr * t.predict(X)
    trees.append(t)
print("scratch mse", mean_squared_error(y, pred).round(4))

# lr and n_estimators are one hyperparameter wearing two hats: halve the
# learning rate and you need roughly twice the trees for the same fit.
from sklearn.ensemble import GradientBoostingRegressor
for lr, n in [(0.3, 100), (0.1, 300), (0.03, 1000)]:
    m = GradientBoostingRegressor(learning_rate=lr, n_estimators=n,
                                  max_depth=3, random_state=0).fit(X, y)
    print(f"  lr={lr:<5} n={n:<5} mse={mean_squared_error(y, m.predict(X)):.4f}")
