Dimensionality Reduction
Two unrelated jobs share this chapter: compressing features so a model trains on less noise, and projecting to two dimensions so a human can look at the data. PCA does the first and can do the second; t-SNE does only the second and is routinely misused for the first. Keeping the two apart is most of what there is to get right here — a t-SNE plot is a picture, not a feature space.
PCA is a rotation you choose by variance
Find the direction in which the data is most spread out and make it your first axis. Then the most spread-out direction perpendicular to that, and so on. You end up with the same data in a rotated coordinate system, ordered so that the early axes carry the most variation — and you compress by keeping the first few and discarding the rest.
$$\Sigma = \tfrac{1}{n}X^{T}X \quad\text{(mean-centred)}, \qquad \Sigma v_i = \lambda_i v_i, \qquad \text{explained ratio} = \frac{\lambda_i}{\sum_j \lambda_j}$$
Each eigenvector vi is a principal component — a direction in the original feature space, and a set of loadings telling you how much each original feature contributes to it. Its eigenvalue λi is the variance the data has along it. The components are mutually orthogonal, which is why PCA also decorrelates: whatever multicollinearity you had is gone by construction.
Because it is a rotation followed by truncation, PCA has an inverse_transform: project down, project back, and you recover the data minus whatever the discarded components held. That reconstruction error is measurable, which is what makes PCA usable as compression and as an anomaly score — and it is exactly the property t-SNE lacks.
compute it with SVD, never by eigendecomposing XᵀX

Forming XᵀX squares the condition number: κ(XᵀX) = κ(X)². At a mildly ill-conditioned κ(X) ≈ 10⁴ you get 10⁸, and double precision carries about 16 digits — so half your significant figures are gone before the eigensolver starts. Taking the SVD of the centred X directly gives the same components without ever forming the covariance matrix, which is what sklearn does. It is the same numerical argument as never implementing the normal equations for least squares by hand.

How many components — and why 95% is often disappointing
Sort the eigenvalues, take the running total, and keep enough components to reach your threshold. Suppose five features give eigenvalues 4.0, 2.5, 1.5, 0.8, 0.2 — summing to 9.0:
Components keptVariance capturedCumulative share
PC14.0 / 9.044.4%
PC1–26.5 / 9.072.2%
PC1–38.0 / 9.088.9%
PC1–48.8 / 9.097.8% ← first to clear 95%
all 59.0 / 9.0100%
Four of five components to reach 95% is a 20% reduction — not the dramatic collapse people expect. That is the honest general lesson: PCA compresses well only when features are strongly correlated, because correlation is the redundancy it exploits. On roughly independent features the eigenvalues are all similar, no direction dominates, and the 95% rule retains nearly everything. If your scree plot is a gentle slope rather than a cliff, PCA is telling you there is not much redundancy to remove — which is useful information, not a failure.
Pick the threshold by what it is for: 95–99% when PCA is preprocessing and you want to lose nothing important; the scree elbow when you are looking for how many real underlying factors there are; exactly 2 or 3 when the output is a plot. And do not report a round number without the variance figure attached — "50 components" means nothing on its own, "50 components, 97% of variance" is a decision.
Scaling decides the answer, with a number
PCA maximises variance, and variance carries the square of your units. So the component ordering is decided by how you happened to record the columns.
FeatureStandard deviationVariance

A ratio of 2.56 × 10¹⁰. PC1 will point almost exactly along the income axis and explain essentially 100% of the variance — and it will have told you nothing you did not already know, because it is approximately just "income, rescaled". Every other feature is invisible. Unstandardised PCA ranks your features by their units.
So standardise first, which makes PCA operate on the correlation matrix rather than the covariance matrix. The one genuine exception is when features are already in the same meaningful unit and their relative variances are the signal — pixel intensities, or returns across assets, where a genuinely more volatile asset should dominate the first factor. Outside that, scale.
And fit on training data only. A PCA fitted on the full dataset has seen the test rows' covariance structure, and the components are built from it — the same leak as fitting a scaler before the split, and just as invisible in the score. Put it in a Pipeline so it refits inside every CV fold.
Scree plot, and the line between reduction and visualisation
t-SNE: a picture, and why it is not a space
t-SNE converts pairwise distances into a probability distribution over neighbours, then searches for a two-dimensional layout whose neighbour distribution has minimum KL divergence from the original. It optimises who is near whom, and deliberately does not preserve anything else. The consequences are specific and each one is a way people misread the plots:
  • Cluster sizes are meaningless. The algorithm expands dense regions and contracts sparse ones to fit them all on one page. A visually large blob is not a bigger or more variable group
  • Distances between clusters are meaningless. Two clusters at opposite corners are not more different than two that are adjacent. Only local neighbourhoods were fitted; the global arrangement is largely an artefact
  • Perplexity changes the picture materially. It sets roughly how many neighbours count as local (5–50). The same data at perplexity 5 and 50 can give layouts you would not guess were related — so report the value, and look at more than one
  • It is stochastic. Different seeds, different layouts. Apparent structure that does not survive a reseed was not structure
  • There is no transform. sklearn's TSNE exposes only fit_transform, and that is not an API oversight — the output is the result of an optimisation over this specific set of points, so there is no function to apply to a new one. It therefore cannot be a step in a pipeline that will ever see new data
the mistake this card exists to prevent

Running t-SNE to two dimensions and feeding those two columns to a classifier as features. It is appealing — the plot showed clean separation — and it is wrong three times over: the coordinates have no meaning outside this run, there is no way to compute them for a new row, and the apparent separation partly reflects t-SNE's tendency to exaggerate gaps. If you want a low-dimensional feature representation, use PCA or UMAP or an autoencoder. t-SNE's output is a figure for a human.

UMAP, and the rest of the toolbox
  • UMAP — the default for visualising embeddings now. Substantially faster than t-SNE, preserves more of the global arrangement, and critically it does provide a transform for new points, so it can legitimately be used for feature engineering. Its knobs are n_neighbors (local versus global emphasis) and min_dist (how tightly points may pack). The axes still mean nothing — do not interpret them
  • Truncated SVD — PCA without the mean-centring step. That sounds like a downgrade and is the entire point: centring a sparse matrix fills in every zero and can turn a manageable TF-IDF matrix into one that will not fit in memory. This is why text and recommender pipelines use Truncated SVD (as LSA) rather than PCA
  • Autoencoders — a neural bottleneck learns a non-linear compression, and reconstruction error doubles as an anomaly score. Needs enough data and tuning to be worth it over PCA, and rarely is on tabular problems
  • Supervised alternatives — LDA maximises class separation instead of variance; PLS finds directions covarying with the target. Reach for these when the reason for reducing dimensions is a downstream prediction, since they optimise for the thing you actually want
  • The standard combination: PCA down to ~50 components, then UMAP or t-SNE to 2. PCA removes noise cheaply and makes the expensive non-linear step both faster and better behaved. This is the canonical single-cell genomics pipeline and it generalises well beyond biology

Mistakes that survive code review
  • Fitting PCA before the train/test split. The components encode the test set's covariance. Same leak as a prematurely fitted scaler, equally invisible, and it inflates every number downstream
  • Not standardising. Without it PCA sorts features by unit magnitude — see the 2.56 × 10¹⁰ table. The result looks like a successful reduction and is a rescaled copy of your widest column
  • Using t-SNE output as features. No transform exists, the coordinates are run-specific, and the separation is partly manufactured
  • Interpreting a t-SNE layout quantitatively. "These two clusters are far apart so they are very different" and "this cluster is large" are both unsupported. Only local neighbourhood membership survived the projection
  • Assuming PCA improves model performance. It is unsupervised — it maximises variance with no knowledge of your target, so if the signal lives in a low-variance direction, PCA discards exactly the thing you needed. It is a preprocessing hypothesis to be tested on validation, never a free win. Boosted trees in particular usually do worse on principal components than on raw features, because rotating destroys the axis-aligned splits they rely on
  • PCA on one-hot or binary columns. Variance on a binary column is a function of its base rate, so components end up ordered by category frequency. Use MCA for categoricals, or reconsider whether reduction is what you need
  • Reporting a component count without the variance. "We used 50 components" is not a justification; "50 components, 97% of variance, and validation AUC was unchanged" is
  • Forgetting PCA destroys interpretability. Every component mixes all original features, so downstream coefficients and SHAP values are about components, not about anything a stakeholder recognises. In a regulated setting that alone can rule it out
Where it earns its place
  • Single-cell genomics — the textbook pipeline. 20,000+ gene dimensions, PCA to ~50, UMAP to 2, cluster, then annotate clusters by known marker genes. Worth noticing that the last step is external validation: the projection is checked against biology rather than trusted on its own, which is why the field's use of this stack is unusually reliable
  • Risk factor models in finance. PCA on a correlated matrix of asset returns extracts orthogonal factors, and the leading components reliably turn out to correspond to recognisable things — a market factor, then sector and style factors. One of the few settings where principal components are genuinely interpretable, because the domain supplies the names
  • Latent semantic analysis and recommenders. Truncated SVD on TF-IDF or on a sparse user–item matrix was the standard approach for years and remains a strong, cheap baseline. Modern embedding models replaced it for quality, not for cost
  • Denoising and compression as preprocessing. Dropping trailing components drops the directions where variance is mostly measurement noise — useful on spectra, sensor arrays and image data, where the noise really is low-variance and isotropic
  • Making an expensive step affordable. Reducing to 50 dimensions before clustering, nearest-neighbour search, or a t-SNE/UMAP run is standard because it attacks the curse of dimensionality directly and cuts the cost of everything downstream
  • Anomaly detection by reconstruction error. Fit PCA on normal data; a point that reconstructs badly lies off the manifold the normal data occupies. Cheap, needs no anomaly labels, and works well when normal behaviour is genuinely low-dimensional
🎯 In an interview

Separate the two purposes in your first sentence. "PCA is a linear rotation into variance-ordered axes — I use it to decorrelate and compress features, and it inverts, so reconstruction error is measurable. t-SNE and UMAP are visualisation: they preserve local neighbourhoods and nothing else." That framing pre-empts most of the follow-ups.

Expect: "What does a principal component represent?" — A direction in the original feature space, chosen to maximise variance subject to being orthogonal to all previous components. The loadings say which original features make it up, and the eigenvalue is the variance along it. Add that you would read the loadings before claiming a component means something.

Expect: "How many components?" — Cumulative explained variance to a stated threshold, or the scree elbow, and never a round number without the variance attached. Then volunteer the caveat that separates people: PCA is unsupervised, so the highest-variance directions are not necessarily the predictive ones — it is a hypothesis you validate, and it frequently hurts tree models because it destroys the axis-aligned structure they split on.

Two things that read as real experience: that PCA should be computed by SVD of X rather than by eigendecomposing XᵀX, because forming XᵀX squares the condition number; and that Truncated SVD exists for sparse data because mean-centring would destroy the sparsity. Do not say you used t-SNE features, and do not read distances or cluster sizes off a t-SNE plot.

In code
PCA is a rotation you can invert; t-SNE and UMAP are visualisations you cannot. Treating a t-SNE layout as features is a mistake this snippet is meant to prevent.
import numpy as np
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.manifold import TSNE
from sklearn.preprocessing import StandardScaler

X, y = load_digits(return_X_y=True)
Xs = StandardScaler().fit_transform(X)

pca = PCA().fit(Xs)
cum = np.cumsum(pca.explained_variance_ratio_)
print("components for 90% variance:", np.searchsorted(cum, .90) + 1, "of", X.shape[1])

# PCA is linear and invertible — you can reconstruct, so it can live in a pipeline
p30 = PCA(n_components=30).fit(Xs)
recon_err = ((Xs - p30.inverse_transform(p30.transform(Xs))) ** 2).mean()
print("reconstruction mse", round(recon_err, 4))

# t-SNE has no transform() for new points and no inverse. It is for looking at,
# not for feeding a model. Distances between clusters are not meaningful either.
emb = TSNE(n_components=2, perplexity=30, init='pca', random_state=0).fit_transform(Xs)
print("tsne output", emb.shape, "| has transform():", hasattr(TSNE(), 'transform'))
