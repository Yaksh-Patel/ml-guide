Weight Initialization
A network's first forward pass happens before any learning, and its activations either hold their scale through the layers or shrink and blow up geometrically. Initialisation is the one chance to set that scale deliberately — and the formulas people memorise as Xavier and He are just the answer to "what variance keeps the signal from dying", derived in two lines.
Zeros fail for a reason worth stating precisely
Setting every weight to zero — or to any single constant — does not merely start badly. It makes learning structurally impossible, and the argument is symmetry rather than scale.
If two units in a layer have identical incoming weights, they compute identical outputs. Identical outputs mean identical gradients. Identical gradients mean identical updates — so they remain identical after the update, and after every update thereafter. A 512-unit layer initialised to a constant has the representational capacity of one unit, permanently.
So randomness is not there to be helpful; it is there to break the symmetry, and any random draw does that. Which leaves the real question: random with what variance?
  • Too large — activations grow layer over layer. Saturating activations lock at their extremes with zero gradient; unbounded ones overflow to NaN
  • Too small — activations shrink toward zero, and so do the gradients flowing back through them. The network computes almost nothing and learns almost nothing
  • The target: keep the variance of the activations roughly constant from layer to layer. Everything below is that one requirement solved
Biases are the exception — initialise them to zero. They carry no symmetry problem, because the weights feeding each unit already differ.
Deriving the variance, then He's factor of 2
Take a unit summing nin independent inputs with weights drawn independently of them. Variances of independent terms add:
$$\operatorname{Var}(z) = n_{\text{in}} \cdot \operatorname{Var}(w) \cdot \operatorname{Var}(x) \quad\Longrightarrow\quad \operatorname{Var}(w) = \frac{1}{n_{\text{in}}} \ \text{ keeps } \operatorname{Var}(z) = \operatorname{Var}(x)$$
That is the whole derivation. Xavier/Glorot then notices the backward pass has the same requirement with nout in place of nin, and compromises between the two by using 2/(nin + nout) — the harmonic-mean-ish middle ground that preserves variance in both directions at once.
Now add ReLU, and watch the derivation break. ReLU sets every negative pre-activation to zero, so it discards half the distribution and halves the variance passing through. With Var(w) = 1/nin, each layer therefore multiplies the activation variance by ½:

Ten layers and the signal is 1,024× smaller than it started. That is a network whose deep layers see essentially nothing, and it is exactly what people hit when they used Xavier with ReLU. He/Kaiming initialisation is the one-character fix: use 2/nin instead of 1/nin, and the factor of 2 cancels ReLU's halving exactly, layer after layer.
$$\text{Xavier: } \operatorname{Var}(w) = \frac{2}{n_{\text{in}} + n_{\text{out}}} \qquad\qquad \text{He: } \operatorname{Var}(w) = \frac{2}{n_{\text{in}}}$$

Note that the standard deviations differ by only √2 ≈ 1.41 — a difference that looks trivial per layer and compounds to 1,024× over ten. That is the lesson of this topic in one line: per-layer factors are multiplicative, so small errors in scale are exponential in depth. Same arithmetic as vanishing gradients, applied to the forward pass.
The rule reduces to: He for ReLU and its variants, Xavier for tanh and sigmoid. Framework defaults are usually reasonable but not always what you want — PyTorch's Linear defaults to a Kaiming-uniform variant with a setting appropriate for leaky ReLU, so if you are stacking tanh layers you should say so explicitly rather than inherit it.

Why this matters less than it used to — and where it still decides everything
Normalisation layers changed the stakes. BatchNorm and LayerNorm re-impose unit scale at every layer on every step, so a mis-scaled initialisation is corrected almost immediately rather than compounding. On a modern normalised architecture you can be somewhat careless and still converge, which is a large part of why these layers were transformative.
"So initialisation is irrelevant now" is the wrong conclusion, for three concrete reasons:
  • The first few steps happen before normalisation has stabilised anything. A wildly scaled init can produce a NaN or a destructive update in step one, and a run that dies at step one never reaches the regime where BatchNorm would have saved it
  • Very deep residual stacks need init to account for depth. Each residual branch adds to the main path, so variance grows with the number of blocks. GPT-2-style init scales residual-branch output weights by 1/√(2N) for N layers — at 48 layers that is 1/√96 ≈ 0.102, a 10× reduction. Without it, activations at the top of a deep stack are far larger than at the bottom before a single gradient step
  • Architectures without normalisation still depend on it entirely — and so do the parts of normalised networks that sit outside the norm layers, such as embeddings and output heads
There is also the special case that is pure practical folklore and genuinely matters: set an LSTM's forget-gate bias to 1. At bias 0 the gate sits at σ(0) = 0.5, so the cell discards half its memory every timestep before learning anything. At bias 1 the gate opens to σ(1) ≈ 0.73 and the default behaviour becomes remember, leaving the model to learn when to forget — which is the easier thing to learn.
And the strongest initialisation is somebody else's trained weights. Where a pretrained backbone exists, fine-tuning from it beats any random scheme by a margin no initialisation formula approaches. In that setting the only thing to initialise is the new head — and reinitialising the backbone is not a choice, it is a mistake.
Mistakes that survive code review
  • Zeros or a constant. Symmetry never breaks; a whole layer behaves as one unit forever. Zeros are correct for biases only
  • Xavier with ReLU. Variance halves per layer — 1/1024 after ten. Use He, and remember the gap is only √2 per layer, which is why it is easy to dismiss
  • Assuming normalisation makes init irrelevant. It buys robustness, not immunity, and it cannot save a run that NaNs on step one
  • Ignoring depth in a residual stack. Variance accumulates across branches; deep models scale residual output weights by 1/√(2N)
  • Reinitialising a pretrained backbone. Discards the single most valuable thing you have. Initialise the new head only
  • Leaving an LSTM's forget-gate bias at 0. The model starts by forgetting half its state every step
  • Assuming the framework default matches your activation. Defaults are tuned for the common case — check when you deviate from it, since nothing will warn you
  • Initialising a layer that follows a norm layer as though scale mattered. The norm will rescale it anyway; the weights that matter there are the norm's own γ and β, which start at 1 and 0 deliberately
  • Not looking at activation statistics once. Print the mean and standard deviation of each layer's activations on one batch before training. A trend across depth tells you the scaling is wrong in seconds, and almost nobody checks
How this shows up in practice
  • He initialisation is why very deep convnets became trainable — it appeared in the paper that first trained networks deep enough to need it, and the argument was exactly the variance-halving above. It is a case where a two-line derivation unlocked an architecture class
  • Transformer init is a specified part of the recipe. Normal with std around 0.02 for weights, residual-branch scaling by 1/√(2N), zeros for biases, and LayerNorm at γ = 1, β = 0. These numbers are copied deliberately across implementations because deviating from them at scale costs training stability
  • Orthogonal initialisation for recurrent weights. An orthogonal matrix has all singular values equal to 1, so repeated multiplication through timesteps neither shrinks nor grows the signal. It is the cleanest possible answer to a product-of-matrices problem, and the natural fit for an RNN's recurrence
  • Embedding tables are initialised small and separately. They sit outside normalisation and their gradients are sparse, so their scale is set independently of the dense layers — and tying input and output embeddings changes what scale is appropriate
  • The diagnostic that catches these problems is trivial and underused: a single forward pass with per-layer activation statistics logged. A steady decay or growth across depth is visible immediately, and it costs one batch
🎯 In an interview

Derive it rather than recite it. "Var(z) = n_in · Var(w) · Var(x), so Var(w) = 1/n_in preserves the scale. Xavier balances that against the backward pass with 2/(n_in + n_out). ReLU then zeroes half the distribution and halves the variance, so He uses 2/n_in — the factor of 2 exactly cancels the halving." Two lines, and it covers both formulas and the reason they differ.

Have the compounding number. Xavier with ReLU loses half the variance per layer, so after ten layers the signal is about 1/1024 of the input. The per-layer standard deviations differ by only √2 ≈ 1.41, which is why the mistake is easy to make and severe to keep — per-layer factors are multiplicative, so small scale errors are exponential in depth. Same arithmetic as vanishing gradients, applied forward.

Expect: "Why not initialise to zero?" — Answer with symmetry, not scale: identical weights give identical outputs, hence identical gradients and identical updates forever, so a 512-unit layer has the capacity of one unit. Randomness exists to break the symmetry; the variance question is separate. And biases should be zero.

The nuanced answer: normalisation layers have made initialisation much more forgiving, but not irrelevant — a bad init can still NaN on step one before BatchNorm stabilises anything, and deep residual stacks need 1/√(2N) branch scaling because variance accumulates across blocks. Then close on the practical point: the best initialisation available is a pretrained checkpoint, and the only thing you initialise then is the head.

In code
Initialisation decided in one line, verified by measuring activation variance layer by layer. If the variance collapses or explodes across depth, nothing else you do will help.
import numpy as np

rng = np.random.default_rng(0)
x = rng.normal(size=(1000, 128))

def propagate(scale_fn, act, depth=12, width=128):
    a = x.copy()
    stds = []
    for _ in range(depth):
        W = rng.normal(0, scale_fn(width), (a.shape[1], width))
        a = act(a @ W)
        stds.append(a.std())
    return np.round(stds, 4)

relu = lambda z: np.maximum(0, z)
tanh = np.tanh

# Too small: signal dies. Too big: it explodes. Both are unrecoverable.
print("naive 0.01 + relu ", propagate(lambda n: 0.01, relu)[:6], "...")
print("naive 1.00 + relu ", propagate(lambda n: 1.00, relu)[:6], "...")

# He/Kaiming: var = 2/fan_in, because ReLU zeroes half the distribution
print("He + relu         ", propagate(lambda n: np.sqrt(2/n), relu)[:6], "...")

# Xavier/Glorot: var = 1/fan_in for symmetric activations like tanh
print("Xavier + tanh     ", propagate(lambda n: np.sqrt(1/n), tanh)[:6], "...")

# Rule: He for ReLU family, Xavier for tanh/sigmoid, zeros for biases only.
# Never initialise weights to zero -- every unit computes the same thing and
# receives the same gradient, so the layer never breaks symmetry.
