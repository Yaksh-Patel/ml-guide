ML Paradigms
Before any algorithm choice, one decision dominates everything downstream: what your data actually brings with it. Labels, no labels, labels you manufacture, or a reward that arrives late. Get the framing wrong and no amount of model tuning recovers it — you will be solving a different problem well.
Supervised — you have the answers
Every row comes with the target. The model learns a mapping f(X) → y, and success is measured against held-out answers you already trust.
$$\text{given } \{(x_i, y_i)\}_{i=1}^{n}, \quad \text{learn } f \text{ minimising } \frac{1}{n}\sum_i L(f(x_i), y_i)$$
This is the paradigm with the most mature tooling and the clearest evaluation story, which is why it should be your default when labels exist. It is also the one where the label definition is the real modelling decision and gets the least scrutiny.
the question nobody asks early enough

"Defaulted" — within 30 days or 90? "Churned" — cancelled, or stopped using? "Fraud" — confirmed by investigation, or flagged by a rule? A model is only as meaningful as its label, and label definitions drift silently when the team that set them moves on. Write the definition down, with the observation window, before you fit anything.

  • Classification: discrete target — default / no default, which of 40 categories
  • Regression: continuous target — expected loss, time to event, demand next week
  • Ranking: the target is an ordering, not a value. Optimising pointwise accuracy here is a classic mis-framing
Unsupervised — structure without answers
Only X. The model finds structure, and there is no ground truth to check it against — which is the defining difficulty, not a detail.
  • Clustering: group similar rows. k-means, DBSCAN, hierarchical
  • Dimensionality reduction: compress while keeping what matters. PCA, UMAP
  • Density estimation / anomaly detection: learn what normal looks like, flag what is not
the evaluation problem

Silhouette and inertia measure whether clusters are geometrically tidy, not whether they mean anything. A clustering can score beautifully and be useless to the business, and it can score poorly and be exactly the segmentation the marketing team needed. Unsupervised results need a human to validate them against a purpose — that step is the work, not an afterthought.

In practice, unsupervised methods most often earn their place as feature generators for a supervised model downstream — a cluster id, a PCA component, an anomaly score.
Self-supervised — manufacture the label from the input
The insight that produced the last decade of progress: you do not need humans to label data if the data can label itself. Hide part of the input, predict it from the rest, and you have a supervised problem with an unlimited supply of examples.
$$\text{mask part of } x \;\longrightarrow\; \text{predict the masked part from the remainder}$$
  • Masked language modelling (BERT): blank 15% of tokens, predict them
  • Next-token prediction (GPT): predict token t+1 from tokens ≤ t
  • Contrastive (CLIP, SimCLR): pull matched pairs together, push mismatched apart. The negatives come free from the batch

The economics are the point. Human labelling costs money per example and caps out in the millions; self-supervision costs compute and scales to trillions of tokens. Pretrain self-supervised on everything, fine-tune supervised on the little labelled data you have — that recipe is now the default for text, images and increasingly tabular data.
Semi-supervised — a few labels, lots of data
The common real situation: 500 labelled rows and 500,000 unlabelled ones, because labelling requires an expert.
  • Pseudo-labelling: train on what you have, predict the rest, keep the confident predictions as labels, retrain. Cheap and effective — and it will happily amplify its own errors, so hold a clean validation set back
  • Consistency regularisation: require the model to give the same answer for two augmentations of the same unlabelled input
  • Active learning: spend your labelling budget on the examples the model is least sure about, rather than at random. Often the single highest-return option
Reinforcement — no labels, only consequences
An agent takes actions, the environment returns a reward, and the reward may arrive long after the action that earned it.
$$\max_{\pi} \; \mathbb{E}\left[\sum_{t} \gamma^{t} r_t\right]$$
Two things make it hard: credit assignment (which of the last fifty moves caused the win?) and exploration (you only learn about actions you actually take). γ discounts the future, which is what makes the sum finite and encodes how patient the agent should be.
Genuinely the right frame for recommendations under long-term engagement, pricing, and RLHF. Genuinely the wrong frame for anything you could have labelled — it is far more expensive to get working.
Four paradigms, by what the data brings with it
Mis-framings that waste a quarter
  • Treating ranking as classification. Predicting click probability per item and sorting is not the same as optimising the ordering. If the metric is NDCG or recall@k, a pointwise classifier is leaving value on the table
  • Reaching for unsupervised because labels are inconvenient. Clustering is not a substitute for a target. If the business question has a right answer, find fifty labelled examples and start supervised — even a weak supervised baseline tells you more than a beautiful clustering
  • Using RL where a bandit would do. If the reward arrives immediately and actions do not change future state, you have a contextual bandit, not a full RL problem. Bandits are vastly simpler and actually converge
  • Believing self-supervised means "no labels needed". It means no human labels for pretraining. You still need labelled data to fine-tune and, non-negotiably, to evaluate
  • Ignoring that anomaly detection is usually one-class. With 0.01% positives, framing it as balanced classification produces a model that predicts "normal" forever and scores 99.99%
  • Letting the label leak. The most common failure across every paradigm: a feature computed after the label event. It shows up as an implausibly good CV score, which is the moment to get suspicious rather than pleased
How the framing is chosen in practice
  • Recommenders are usually a hybrid. Self-supervised or contrastive pretraining for embeddings, supervised ranking on engagement labels, and increasingly a bandit or RL layer on top for long-term value. Three paradigms in one system, each doing what it is best at
  • Fraud and credit are supervised with a label-delay problem. You cannot label a default until the observation window closes, so your freshest data is unlabelled by construction. That drives everything from retraining cadence to how you evaluate
  • Foundation models made pretrain-then-finetune the default. For text and vision, training from scratch is now the unusual choice and needs justification
  • Active learning where labels are expensive. Medical imaging, document review, anything needing a specialist. Spending the budget on uncertain examples routinely beats labelling ten times as many at random
🎯 In an interview

When handed a vague problem, frame it out loud before proposing a model. "What is the label, and when does it become available? How many labelled examples exist? Does an action change what happens next?" Those three questions choose the paradigm, and asking them is most of the signal being measured.

Expect: "How would you build this with almost no labels?" — Pretrain self-supervised or start from a foundation model, fine-tune on what you have, and use active learning to spend the labelling budget where the model is least certain.

Also common: "When is reinforcement learning the right tool?" — When actions change future state and reward is delayed. If neither holds, say so and propose a bandit instead. Declining to over-reach reads as judgement, not ignorance.

Do not propose clustering for a problem that has a right answer.

In code
The three paradigms on one dataset, so the difference is in the code rather than in prose: labels used, labels ignored, and reward observed.
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.ensemble import RandomForestClassifier
from sklearn.cluster import KMeans
from sklearn.metrics import accuracy_score, adjusted_rand_score

X, y = make_blobs(n_samples=600, centers=3, cluster_std=1.6, random_state=0)

# SUPERVISED — labels are the target
clf = RandomForestClassifier(random_state=0).fit(X[:400], y[:400])
print("supervised acc  ", accuracy_score(y[400:], clf.predict(X[400:])).round(3))

# UNSUPERVISED — same X, labels never seen; scored against them only to inspect
km = KMeans(n_clusters=3, n_init=10, random_state=0).fit(X)
print("cluster ARI     ", adjusted_rand_score(y, km.labels_).round(3))

# SELF-SUPERVISED — the label is manufactured from the input itself
mask = np.random.default_rng(0).random(X.shape) < 0.3
X_corrupt = np.where(mask, 0.0, X)
# task: reconstruct X from X_corrupt. No human labels involved at all.

# REINFORCEMENT — no labels, only reward for an action taken
def reward(action, state): return 1.0 if action == np.argmax(state) else -0.1
