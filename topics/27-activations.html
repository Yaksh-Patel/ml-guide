Activation Functions
Two jobs, and they pull in different directions. In the forward pass the activation supplies the non-linearity without which depth collapses. In the backward pass its derivative multiplies into every gradient that passes through it — so the choice decides whether a deep network trains at all. The history of this topic is the history of that second job being taken seriously.
Why sigmoid lost, in one multiplication
Backpropagation multiplies one activation derivative per layer into the gradient. So the derivative's magnitude compounds geometrically with depth, and that single fact decided which activations survived.
$$\sigma'(z) = \sigma(z)\big(1 - \sigma(z)\big) \qquad\Longrightarrow\qquad \max_z \sigma'(z) = \sigma'(0) = 0.25$$
The sigmoid's derivative peaks at 0.25 — and that is its best case, at the single most favourable input. Ten layers of sigmoid multiply at most:
$$0.25^{10} = 9.5 \times 10^{-7}$$
A gradient arriving at the output is a millionth of its size by the time it reaches the first layer, in the most optimistic case available. Away from zero it is far worse — σ′(4) = 0.018, σ′(8) = 0.0003 — so any unit that has saturated contributes essentially nothing, permanently.
ReLU's derivative is exactly 1 for every positive input. Ten layers multiply 1 × 1 × … × 1 = 1. The gradient arrives at the first layer at full strength. That is the entire reason ReLU replaced sigmoid in hidden layers — not empirical luck, but the observation that a derivative of 1 is the only value that does not compound.

Sigmoid and tanh still have their places — sigmoid at a binary output, where a bounded [0,1] value is the answer, and both inside LSTM cells, where the gates need bounded outputs by design. What they cannot be is the activation of a deep hidden stack.

Dying ReLU, and the bias shift nobody mentions
ReLU's derivative for negative input is 0, not small — zero. A unit whose pre-activation is negative for every training example outputs 0, receives gradient 0, and therefore never updates again. It is not learning slowly; it is permanently removed from the network, and its parameters are dead weight.
Causes are specific: a learning rate high enough for one update to drive the bias strongly negative, poor initialisation, or a large negative gradient from an outlier batch. The remedies:
  • Measure it before fixing it. Log the fraction of units with zero activation across a validation batch. A few percent is normal and healthy sparsity; 40% is a problem. Most people switch activations on suspicion rather than measurement
  • He initialisation — variance 2/n_in, derived specifically for ReLU's halved output variance. The right default, and it removes most dying-ReLU cases at the source
  • Leaky ReLU keeps a gradient of α ≈ 0.01 on the negative side, so a unit can always recover. Cheap insurance; slightly less sparsity
  • Lower the learning rate, or add warmup — most death happens in the first few hundred steps, when updates are largest
the subtler problem: ReLU is not zero-centred

For a zero-mean pre-activation z ~ N(0,1), ReLU's output has mean 1/√(2π) ≈ 0.399 — positive, always, because every negative value was clipped to zero. So each ReLU layer hands the next layer inputs with a positive mean offset, and that shift accumulates with depth.

A consistently positive input means all weights in a unit receive gradients of the same sign, so they can only move together rather than independently — the zig-zagging that makes optimisation slower. This, not dying units, is the main reason the smooth alternatives were sought: ELU, GELU and Swish all allow small negative outputs, pulling the mean activation back toward zero. It is also part of why batch normalisation helps so much after a ReLU — it re-centres exactly this drift.

GELU: a soft gate rather than a hard one
ReLU is a hard gate — it multiplies the input by 1 or by 0. GELU multiplies the input by the probability that a standard normal falls below it:
$$\text{GELU}(x) = x \cdot \Phi(x), \qquad \Phi(x) = \mathbb{P}(Z \le x),\ Z \sim \mathcal{N}(0,1)$$
So instead of "keep it or discard it", the rule is "keep the fraction of it that its magnitude justifies". Large positive inputs pass almost untouched; large negatives are almost entirely suppressed; and in between the gate opens gradually.

Two properties matter. It is smooth everywhere, so there is no kink at zero where the derivative jumps — gentler for the second-order structure that adaptive optimisers estimate. And it is non-monotonic: it dips to −0.170 around x = −0.75 before returning toward zero, so a small negative pre-activation produces a small negative output rather than nothing. Both the zero-centring and the escape from dead units come for free.
SwiGLU is the current answer in large language models, and it earns its place with an accounting trick worth knowing. It splits the feed-forward input into two projections and uses one to gate the other — Swish(xW) ⊗ (xV) — which needs three weight matrices instead of two. To keep the parameter count unchanged, implementations shrink the hidden width from 4d to 8d/3. At d = 4,096 that is 10,923 instead of 16,384, and the totals land at 134.21M against 134.22M — essentially identical parameters, measurably better loss. That is why LLaMA-family models have an oddly-shaped feed-forward block.
Output activations are chosen by the task
Hidden activations are a judgement call. Output activations are not — the task determines them, and getting this wrong produces a model that trains without complaint and cannot express the right answer.

softmax where sigmoid belongs — the most common output bug

Softmax normalises across classes, so its outputs must sum to 1. That encodes mutual exclusivity: more probability for one class necessarily means less for another. Correct when exactly one label is true.

For multi-label it is simply wrong. An image can be both "cat" and "outdoors", and the honest answer is P(cat) = 0.9 and P(outdoors) = 0.9 — which softmax cannot represent, because 0.9 + 0.9 > 1. It will be forced to split the mass and report roughly 0.5 each, so the model looks uncertain about two things it is confident about. Use K independent sigmoids: each output is its own binary question.

Softmax needs the max subtracted before exponentiating. A float64 exponential overflows just past e⁷⁰⁹ ≈ 8.2 × 10³⁰⁷, so a logit of 710 gives inf, and inf/inf is NaN. Subtracting the row maximum leaves the result mathematically unchanged — the constant cancels top and bottom — while making the largest exponent exactly e⁰ = 1. Framework implementations do this; hand-written ones frequently do not, and the symptom is a loss that becomes NaN once logits grow confident. This is also why you should pass logits to CrossEntropyLoss rather than pre-softmaxed probabilities: the fused version is the numerically stable one.
Mistakes that survive code review
  • Sigmoid or tanh in a deep hidden stack. 0.25 per layer compounds to 10⁻⁶ over ten layers at best. ReLU or GELU
  • ReLU on the output. Clips every negative prediction to zero, so a regression model can never predict below zero and half its error signal disappears
  • Softmax for multi-label. Forces mutual exclusivity that does not exist. Independent sigmoids
  • Double-applying softmax. Passing already-softmaxed probabilities into a loss that applies softmax internally — CrossEntropyLoss in PyTorch expects raw logits. It trains, badly, and the gradients are wrong rather than absent, which makes it hard to spot
  • Switching activations because you suspect dead units. Measure the zero-activation fraction first. Some sparsity is healthy; the fix for a real problem is usually He initialisation or a lower learning rate, not a different activation
  • Hand-rolling softmax without the max subtraction. Works until logits get large, then NaN. Same class of bug as forgetting log1p
  • Assuming a newer activation will help. GELU over ReLU is worth a fraction of a percent in transformers and usually nothing in a small CNN. It is a real but small effect, and it is not where a struggling model's problem lies
  • Putting an activation after the final normalisation in a residual block. Placement inside a block matters and is architecture-specific; copy the reference implementation rather than reasoning from first principles
What is actually deployed
  • Transformers use GELU, and large language models have moved to SwiGLU. BERT's ablations picked GELU over ReLU on measured task performance, and it became the encoder standard. The LLaMA/PaLM generation replaced it with gated variants and shrank the feed-forward width to 8d/3 to hold parameters constant — a change worth understanding because it explains the architecture's unusual proportions
  • Convolutional networks still run ReLU. ResNet's ReLU has not been displaced for general vision work; the smooth alternatives (SiLU in EfficientNet and MobileNetV3) win by small margins at some cost in inference speed, which matters when the model runs on a phone
  • LSTM's tanh-and-sigmoid pairing is deliberate, not legacy. Sigmoid on the gates because a gate must be a bounded fraction in [0,1]; tanh on the cell state because it must stay bounded to keep the recurrence stable. This is the one place where saturating activations are the correct engineering choice
  • Quantised and edge deployment prefers ReLU. Its piecewise-linear form quantises cleanly to int8, while smooth activations need lookup tables or polynomial approximations. On-device model choices are often driven by this rather than by accuracy
  • Output layers are where activation bugs actually cost money. Multi-label classifiers built with softmax, and regression heads with ReLU that cannot predict a loss, are the failures that reach production — because both train quietly and only the predictions are wrong
🎯 In an interview

Answer "why ReLU over sigmoid" with the multiplication. "Backprop multiplies one activation derivative per layer. Sigmoid's peaks at 0.25, so ten layers give at most 0.25¹⁰ ≈ 10⁻⁶ — and that is the best case, at z = 0. ReLU's derivative is exactly 1 for positive inputs, so nothing compounds." A specific number beats "sigmoid causes vanishing gradients" by a wide margin.

Expect: "What is dying ReLU and how do you fix it?" — Negative pre-activation gives output 0 and gradient 0, so the unit is permanently removed, not merely slowed. Then be the candidate who measures: log the zero-activation fraction, because some sparsity is healthy. Fixes in order — He initialisation, lower learning rate or warmup, then Leaky ReLU. And volunteer the deeper issue: ReLU's output mean is 1/√(2π) ≈ 0.4, not 0, and that positive bias shift accumulating through depth is the real reason GELU and Swish were sought.

Expect: "Softmax or sigmoid?" — Softmax normalises across classes, so it encodes mutual exclusivity: right for single-label, wrong for multi-label, where an image being both "cat" and "outdoors" needs two independent sigmoids. Add the numerical note — subtract the row max before exponentiating, since e⁷¹⁰ overflows float64 — and that you pass logits to the loss rather than probabilities.

Explain GELU as a soft gate: x·Φ(x) keeps the fraction of the input its magnitude justifies, rather than ReLU's all-or-nothing. It is smooth and non-monotonic — dipping to about −0.17 near x = −0.75 — which fixes both dead units and the mean-shift in one function.

In code
Every activation in the comparison table, implemented and differentiated, plus the saturation check that explains why sigmoid stopped being used in hidden layers.
import numpy as np

def sigmoid(x): return 1 / (1 + np.exp(-x))
def tanh(x):    return np.tanh(x)
def relu(x):    return np.maximum(0, x)
def leaky(x, a=0.01): return np.where(x >= 0, x, a * x)
def elu(x, a=1.0):    return np.where(x >= 0, x, a * (np.exp(x) - 1))
def gelu(x):    return 0.5 * x * (1 + np.tanh(np.sqrt(2/np.pi) * (x + 0.044715 * x**3)))
def swish(x):   return x * sigmoid(x)
def softmax(x):
    x = x - x.max(-1, keepdims=True)          # subtract max or exp() overflows
    e = np.exp(x)
    return e / e.sum(-1, keepdims=True)

# Derivatives — this column is what decides whether depth trains
d_sigmoid = lambda x: sigmoid(x) * (1 - sigmoid(x))     # max 0.25 at x=0
d_tanh    = lambda x: 1 - np.tanh(x) ** 2               # max 1.0 at x=0
d_relu    = lambda x: (x > 0).astype(float)             # exactly 1 or 0

# Why sigmoid kills deep nets: chain 10 layers of gradient <= 0.25
print("sigmoid grad at |x|=4:", d_sigmoid(np.array([4.0]))[0].round(6))
print("10 stacked layers    :", (0.25 ** 10))           # 9.5e-07, gone

# Dying ReLU: a unit whose pre-activation is always negative gets zero
# gradient forever. Leaky/ELU/GELU exist to keep a small slope alive.
z = np.array([-3., -1., 0., 1., 3.])
for f in (relu, leaky, elu, gelu, swish):
    print(f"{f.__name__:6}", np.round(f(z), 3))
