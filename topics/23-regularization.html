Regularization
Every regulariser makes the same bet: accept more training error in exchange for less test error. What separates them is the assumption each one encodes about which models are implausible before you have seen any data — and that assumption, not the formula, is what you are choosing when you pick L1 over L2 or dropout over weight decay.
$$\text{objective} = \underbrace{\text{data loss}}_{\text{fit the sample}} \;+\; \lambda \cdot \underbrace{\text{penalty}}_{\text{prefer simpler models}}$$
The penalty is a prior
L1 and L2 look like arbitrary choices until you write down where they come from. Maximum likelihood picks the weights that best explain the data. Maximum a posteriori multiplies in a prior belief about the weights first:
$$\hat w = \arg\max_w\ \underbrace{p(\text{data} \mid w)}_{\text{likelihood}} \cdot \underbrace{p(w)}_{\text{prior}} \quad\Longrightarrow\quad \arg\min_w\ \big[\underbrace{-\log p(\text{data} \mid w)}_{\text{data loss}} \;\underbrace{-\log p(w)}_{\text{penalty}}\big]$$
Take the negative log of a prior and you get the penalty term, which fixes the forms exactly:
  • Gaussian prior on the weights → −log p(w) ∝ Σwᵢ² → this is L2 / ridge. The belief is that weights are small and no coordinate is special
  • Laplace prior (a sharp peak at zero with heavy tails) → −log p(w) ∝ Σ|wᵢ| → this is L1 / lasso. The belief is that most weights are exactly zero and a few are large
So the choice between them is a modelling statement, not a preference: do you believe every feature contributes a little, or that most contribute nothing? λ is the strength of that belief. It also explains why the best λ grows as your dataset shrinks — with less data, the prior should carry more of the answer.
Why L1 zeroes and L2 does not — the exact answer
The usual explanation is geometric: the L1 constraint region is a diamond with corners on the axes, and an expanding loss contour touches a corner before a face. That is right and it is a picture. Here is the same fact as arithmetic you can check.
With orthonormal features both penalties have closed-form solutions in terms of the unpenalised estimate — and the two formulas are the whole story:
$$w^{\text{lasso}} = \operatorname{sign}(w^{\text{ols}})\cdot\max\big(|w^{\text{ols}}| - \lambda,\ 0\big) \qquad\qquad w^{\text{ridge}} = \frac{w^{\text{ols}}}{1 + \lambda}$$
L1 subtracts a constant and clips at zero. L2 multiplies by a constant. Run λ = 0.5 through both:

Everything with |w| below λ is gone under L1, exactly and permanently. Under L2 a coefficient is multiplied by 0.667 no matter how small it already is — 0.1 becomes 0.067, then 0.045, approaching zero and never arriving. Subtraction has a floor; multiplication does not.

The gradient view says the same thing in one line. The derivative of |w| is sign(w) — magnitude 1 regardless of how small w is, so the push toward zero never weakens and eventually lands. The derivative of w² is 2w, which vanishes as w → 0, so the push dies out before it arrives. Once L1 has a weight at zero, the subgradient interval [−λ, λ] holds it there against any data gradient smaller than λ.

the failure that gets lasso mistaken for a feature-importance tool

Give lasso two strongly correlated features that are both genuinely predictive and it keeps one and zeroes the other — because keeping one is enough to fit the data, and one coefficient costs less penalty than two. Which one survives is decided by noise. Refit on a bootstrap sample and the other may win.

So a lasso path is not a statement about which features matter; it is one sparse solution among several that fit almost equally well. Elastic net exists precisely for this — the L1 term keeps the sparsity and the L2 term makes correlated features share, so a whole correlated group enters or leaves together. If you are using L1 to decide what to tell a stakeholder is important, check the stability across resamples first.

Scale first, always. The penalty charges per unit of coefficient, and a coefficient's magnitude is inversely proportional to its feature's scale. Express income in thousands instead of dollars and its coefficient multiplies by 1,000 — so under L2 its penalty contribution multiplies by 10⁶. Regularising unstandardised features means your choice of units decided which features got selected, which is not a modelling decision anyone intended to make.
And do not penalise the intercept. It only shifts the output level, so shrinking it biases predictions toward zero for no benefit — a model on data with mean 50 cannot fit if its intercept is being pulled to 0. sklearn excludes it automatically; hand-rolled implementations frequently do not.
Dropout: an ensemble you never enumerate
During training, zero each unit independently with probability p. Every minibatch therefore trains a different subnetwork, and since a layer of n droppable units has 2n possible masks, the network is an implicit ensemble over an astronomically large family sharing one set of weights. At n = 1,000 that is 2¹⁰⁰⁰ subnetworks — the point being that it is an ensemble you get for free, never by enumeration.
The mechanism that matters: no unit can rely on any particular other unit being present, so the network cannot build brittle chains where one feature detector depends on one upstream neighbour. It is forced into redundant, distributed representations.
$$\text{train:}\quad a' = a \cdot \frac{\text{Bernoulli}(1-p)}{1-p} \qquad\qquad \text{inference:}\quad a' = a$$
That 1/(1−p) factor is the detail worth knowing. At p = 0.5 the surviving activations are scaled by 2, so the expected activation entering the next layer is the same during training as at inference — which is why inference needs no adjustment at all. This is "inverted dropout", and it is why model.eval() is sufficient rather than requiring a manual rescale. Forget it and every activation at inference is roughly double what the next layer was trained to expect.
Modern rates are much lower than the famous 0.5. That number comes from very wide fully-connected layers in 2012, and repeating it in a transformer is a mistake — transformers typically use 0.1, sometimes 0.0 at large scale where the data itself is the regulariser. Dropout also largely left convnets when batch normalisation arrived: BN's minibatch noise is itself regularising, and the two interact badly, since the activation statistics BN estimated during training do not match the undropped statistics at inference.
Weight decay is not L2 once you use Adam
These are treated as synonyms and they are only equivalent under plain SGD. The distinction is the entire content of the AdamW paper and the reason every transformer is trained with AdamW rather than Adam.
Under SGD they coincide. Adding λ‖w‖² to the loss contributes 2λw to the gradient, and subtracting η·2λw from the weight is the same thing as decaying the weight directly. Two descriptions, one update.
Under Adam they diverge. Adam divides each parameter's update by an estimate of its gradient magnitude. If the penalty enters through the loss, its gradient gets divided too:
$$\text{Adam (L2 in the loss):}\ \ w \leftarrow w - \eta\,\frac{\hat m_t + 2\lambda w}{\sqrt{\hat v_t} + \epsilon} \qquad\qquad \text{AdamW:}\ \ w \leftarrow w - \eta\,\frac{\hat m_t}{\sqrt{\hat v_t} + \epsilon} - \eta\lambda w$$
In the first form, a parameter with historically large gradients has a large √v̂, so its decay is divided down — the parameters carrying the most signal get the least regularisation, which is the opposite of the intent. The effective penalty strength ends up coupled to each parameter's gradient history, which is not a prior anyone would choose.
AdamW applies the decay directly to the weight, outside the adaptive rescaling, so it means the same thing for every parameter. In practice: use AdamW, and remember that its weight_decay is not comparable to a loss-based L2 λ — the two need separate tuning, and copying a value across is a common way to get accidentally unregularised training. Also exclude biases and normalisation parameters from decay, as every reference transformer implementation does.
Early stopping and label smoothing
Early stopping is regularisation, and for a linear model trained by gradient descent from zero it is approximately equivalent to L2 with a λ that shrinks as steps accumulate — each step lets the weights grow a little further from the origin, so stopping early is a bound on weight norm imposed by the clock. That is why it composes with, rather than replaces, an explicit penalty.
Label smoothing replaces a hard target of 1 with 1 − ε, distributing ε over the other classes. At ε = 0.1 with 10 classes the true class is 0.9 and each other class is 0.1/9 = 0.0111.
Its purpose is specific: a hard target of exactly 1 is only reachable by driving the correct logit infinitely far above the others, so cross-entropy keeps pushing the logit gap wider forever and the model becomes progressively more overconfident. A soft target has a finite optimum, so the gap stops growing. It is a calibration fix as much as a regulariser, and it is standard in transformer and image-classification training for that reason.

These are complementary because they constrain different things. A transformer stack typically runs dropout, AdamW decay, LayerNorm, label smoothing and early stopping simultaneously, and removing any one measurably changes the result.
Mistakes that survive code review
  • Regularising unstandardised features. The penalty is denominated in coefficient units, so your choice of units picks the features. Scaler and model inside one Pipeline
  • Guessing λ. The right value spans orders of magnitude and depends on n and on the feature scaling. Search log-spaced, and re-search when the dataset size changes materially
  • Tuning λ on the test set. λ is a hyperparameter like any other. Selecting it on the data you then report makes the report optimistic by an unknown margin
  • Using L2 in the loss with Adam and calling it weight decay. The penalty gets divided by the adaptive term, so well-signalled parameters end up least regularised. Use AdamW, and tune its weight_decay independently rather than reusing an L2 value
  • Reading a lasso path as feature importance. Among correlated features it keeps one arbitrarily. Check stability across bootstraps, or use elastic net so groups move together
  • dropout = 0.5 by default. Right for 2012's wide fully-connected layers, wrong for a transformer, which wants ~0.1. And avoid stacking dropout on batch norm — they fight over the activation statistics
  • Penalising the intercept or the norm parameters. The intercept only sets the output level; biases and LayerNorm gains should be excluded from decay, as reference implementations do
  • Adding regularisation to fix a bias problem. Regularisation trades variance for bias. If train and validation error are both high, the model is underfitting and more penalty makes it strictly worse — check the learning curve before reaching for λ
  • Forgetting dropout is active in training mode. Evaluating without model.eval() gives noisy, pessimistic numbers; training with it off silently removes the regulariser. Both are common and neither raises an error
How this shows up in real systems
  • Transformer training is a stack of regularisers. AdamW decay around 0.01–0.1 with biases and norms excluded, dropout 0.1, label smoothing 0.1, warmup plus decay on the learning rate. None is optional at moderate scale, and the recipe is stable enough across models that deviating from it is usually a bug rather than an innovation
  • Elastic net in genomics. Twenty thousand gene-expression features against a few hundred samples, with genes in strongly correlated pathways. Pure L1 would pick one gene per pathway at random and produce a different answer on every resample; the L2 component makes a pathway enter as a group, which is both more stable and more biologically meaningful
  • Embedding regularisation in recommenders. L2 on user and item vectors stops entities with two interactions from acquiring extreme embeddings — the cold-start case, where the data cannot support a confident representation and the prior has to carry it
  • Regulated linear models. Ridge on a logistic scorecard keeps any single coefficient from dominating, which is partly a stability requirement and partly a governance one: a score that swings on one feature is hard to defend and fragile under population shift
  • Augmentation as the dominant regulariser in vision. Crops, flips, colour jitter, mixup, cutmix. Worth separating from the others because it adds information — the knowledge that a label is invariant to a transform — rather than merely restricting the model. When it applies, it beats penalty tuning
🎯 In an interview

Expect: "Why does L1 give sparsity and L2 not?" — Give the arithmetic rather than the diamond picture. With orthonormal features, lasso is soft-thresholding — subtract λ and clip at zero — while ridge multiplies by 1/(1+λ). Subtraction has a floor, multiplication does not, so anything below λ is eliminated exactly and nothing under ridge ever arrives at zero. If you want the gradient version: d|w|/dw = ±1 regardless of magnitude, while d(w²)/dw = 2w vanishes as w → 0.

Frame the choice as a prior. "L2 is a Gaussian prior on the weights, L1 a Laplace prior — so the question is whether I believe every feature contributes a little or that most contribute nothing." That reframing turns a memorised comparison into a modelling argument, and it explains why λ should be larger on small datasets.

The differentiator: know that weight decay ≠ L2 under Adam. If the penalty goes through the loss, Adam divides it by the per-parameter second-moment estimate, so parameters with the largest gradients get the least decay — the opposite of the intent. AdamW applies it outside the adaptive term. Very few candidates raise this, and it is the reason every modern transformer uses AdamW.

Do not say "dropout 0.5 because the paper said so" (that was wide FC layers in 2012; transformers use ~0.1), and do not propose regularisation for a model that is underfitting — check whether train error is already high first.

In code
L1, L2 and elastic net on correlated features, which is the case that separates them: L2 shares the coefficient, L1 picks one arbitrarily.
import numpy as np
from sklearn.linear_model import Ridge, Lasso, ElasticNet
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(0)
x = rng.normal(size=1000)
X = np.column_stack([x, x + .01*rng.normal(size=1000), rng.normal(size=1000)])
X = StandardScaler().fit_transform(X)         # never regularise unscaled features
y = 3*X[:, 0] + rng.normal(0, .5, 1000)       # only feature 0 (and its twin) matter

for name, m in [('ridge  L2', Ridge(alpha=10)),
                ('lasso  L1', Lasso(alpha=.1)),
                ('elastic  ', ElasticNet(alpha=.1, l1_ratio=.5))]:
    print(f"{name}", m.fit(X, y).coef_.round(3))
# ridge   -> [1.5, 1.5, 0.0]  splits the weight across the correlated pair
# lasso   -> [3.0, 0.0, 0.0]  keeps one, zeroes the other; which one is arbitrary
# elastic -> between the two, which is why it is the safe default

# Early stopping and dropout are regularisers too — same job, different mechanism
print("\nlasso path (features surviving as alpha grows):")
for a in (.01, .05, .1, .5, 1.0):
    print(f"  alpha={a:<5} nonzero={np.count_nonzero(Lasso(alpha=a).fit(X, y).coef_)}")
